# 任務：輸出 14 頁架構／流程圖的逐格草圖規格（純文字，不要 XML）

你要產出的是**一份結構化純文字規格**，之後由別人拿去用 drawio MCP 照著畫。

**硬性限制：**

- **不要輸出任何 XML、mxGraph、drawio 標籤、程式碼或座標。** 只輸出下面指定格式的純文字。
- 不要修改 repo 裡任何檔案，不要跑 git 指令。你的產出就是 stdout。
- 全程用繁體中文，名詞一律照下面的名詞表，不要自己造詞、不要用英文同義詞代換。
- 範圍是**骨架草圖**：每頁畫主要方塊、泳道、連線、判斷分支，看得出這頁回答什麼問題、結構長什麼樣。**不要**列訊息碼全集、不要逐項抄檔案欄位、不要把一頁畫成三十格。每頁方塊數控制在 8–16 格。

## 背景事實（這是契約，不要改寫也不要自己發明規則）

### 兩方與兩個情境

承諾關係只有兩方：**使用者**（用 VK 管理工具的人，被承諾的一方）↔ **VK**（vendor_kit，引擎與薄殼的維護者，提出承諾的一方）。

使用者有兩個情境：

- **導入**：這個 repo 要用別人做好的工具。
- **出貨**：這個 repo 自己做了一套工具，要給別的 repo 用。

同一個 repo 可以只做一件，也可以兩件都做。

### 介面：11 個 VK recipe + 一支啟動器

VK recipe 的寫法是 `just vendor_kit <recipe>`，全部收在 `vendor_kit` 這一個命名空間底下。

- 常用三個：`add`、`upgrade`、`dev`
- 進階八個：`remove`、`undev`、`update`、`sync`、`install`、`uninstall`、`prune`、`help`
- 另有一支首次導入用的啟動器 `bootstrap.sh`（下載引擎 + 呼叫 `install`，再跑 = 修復）

語意固定三組：

- 做得了就反得回：`add`↔`remove`、`dev`↔`undev`、`install`↔`uninstall`
- 查與套用分開：`update` 只查、不改任何檔；`upgrade` 才套用
- 不成對的三個必須無害：`sync`、`prune`、`help` 不得改任何進 git 的檔

### VK 組件與物件

- **引擎**：執行 VK recipe 的主程式，以容器 image 發布，在容器內跑。
- **薄殼**：`.vendor_kit/` 內由引擎產生、隨 repo 進 git、供使用者呼叫 VK 的一組檔。薄殼五檔是 `.vendor_kit/entry.just`、`vendor.just`、`log.sh`、`.gitignore`、`ci/check.sh`。薄殼整體只做啟動與轉發，不承載產品規則，**不解讀 repo 內容的意義**。
- **啟動器**：從主機啟動引擎的入口；薄殼內的 POSIX sh 片段與 `bootstrap.sh` 都是啟動器。
- **工具 image**：封裝單一工具出貨內容的**純資料**容器 image，VK 不把它當程式執行、也不驗證它能不能跑。
- **引擎 image**：裝載引擎的容器 image。
- **registry**：存放並提供工具 image 與引擎 image 的服務。
- **image 引用**：`<名稱>:<tag>@sha256:<digest>`。tag 給人看、不鎖內容；digest 鎖內容、不說版本。

### 安裝目錄與唯一版本來源

- **安裝目錄** = `.vendor_kit/` 的直接父目錄，也是 VK 的安裝單位。一個 repo 可以有多個安裝目錄，各自一份版本鎖定行、一個引擎、一份 `.vendor_kit/`，互不共享。**安裝目錄禁止巢狀**（install 時上層或下層已有安裝目錄就以 1 拒絕）。
- VK recipe 只准在安裝目錄執行，在別處就以 1 拒絕並印出該切到哪裡，唯讀 recipe 也沒有例外。
- **版本鎖定行**寫在 `.vendor_kit/version.toml`，進 git，**是唯一的一份版本真相**。引擎行的契約是「唯一符合 `^vendor_kit[[:space:]]*=` 的正規行」，命中數必須恰為 1；工具行在 `[tools]` 表下每個工具一行。
- **本機覆寫**寫在 `.vendor_kit/version.local.toml`，不進 git，只覆蓋已存在的版本鎖定行，不是第二份真相。它指到**本機開發來源**（工具是本機目錄，引擎是本機 image）。
- `.vendor_kit/.gitignore` 涵蓋 `cache/`、`gen/`、`log/`、`version.local.toml`、`.tmp.*`；這份清單就是「自動化可以自己寫」的界線。
- **`cache/`** 放已展開的工具內容（不進 git，可由版本鎖定行決定性重建）；**`gen/`** 放供 just 載入的產出（`gen/tools.just` 每個 `<ns>` 一行）；**印記**記本機工具內容的版本與**逐檔指紋**。
- **repo 檔**是使用者擁有的檔；**VK 檔**是 `.vendor_kit/` 內由 VK 管的檔。

### 結束碼四值（契約）

- `0` 成功（含 warn）
- `1` 失敗或需人處理
- `2` 完成但要人接手：有合併衝突待人解，或 `update --exit-code` 查到有新版
- `3` 現有薄殼、檔案、引擎的組合要先升級或退回才能繼續

`3` 是唯一零寫入的碼，救援路徑亦同（救援路徑 = `install`、`upgrade vendor_kit`、`sync` 的不符判定、`help`，永久可用）。一次處理多個工具只回一個碼，回最需要處理的那個：`1` > `2` > `0`。任何非 0 都要印出原因，需人處理的另附可直接複製的指令。

### 可寫 recipe 的固定時序五步

1. 建**執行紀錄**（早於任何寫入、任何拉 image、任何起引擎）
2. 建**進度檔**（早於第一個內容寫入；`--dry-run` 例外，不建）
3. 不帶工具名、一次處理多個工具時，先對全部工具做**完整預檢**，任一項不過就整體不動、以 1 結束並列出每個不過的原因
4. **寫入**
5. **最後才改版本鎖定行**（工具層可寫 recipe 回 1 時該工具的鎖定行不動）

可寫 recipe 開始前發現未完成的進度檔就先恢復再繼續；唯讀 recipe 只偵測、不自動恢復。明列例外：升引擎先改鎖定行再由新引擎接手。

### 初始檔與基準版合併

- **初始檔**由工具提供、VK 導入 repo 後交由使用者維護，建立後就是 repo 檔。
- **基準版**是上次套用的初始檔原版全文（合併的共同祖先）。**基準版合併**的輸入是三者：基準版、目前 repo 檔、新版初始檔。留下衝突標記時對外是 `2`。
- metadata 記每個初始檔的逐檔狀態：`managed`／`appended`／`declined`／`unmanaged`／`deleted`；被拒絕的版本記在 `declined_hash`。
- metadata 的紀錄是 `remove` 與 `uninstall` **唯一的刪除依據**；append 型只刪原文相同且整份檔恰好一處命中的那一行，零處或多處都只 warn。
- 套用策略寫在工具的 `init.toml`（例如 `strategy = "append"`）。幾乎必已存在的那類初始檔（根 `.gitignore`、`.dockerignore`、`.editorconfig`）只能用 append 型。

### CI 模式

環境變數 `CI` 非空、又不是 `0` 或 `false` 就是 CI 模式；進 git 的檔一律不准寫，遇到要寫就以 1 結束。CI 模式下紅燈是**封閉清單五項**：薄殼不符、基準版落後、未完成導入、任何本機覆寫、需要改進 git 的檔。清單外的提醒不紅燈。**CI 檢查腳本** `.vendor_kit/ci/check.sh` 自己設 `CI=1`，給使用者接進自己的 CI。

### 版本與相容性

- **介面版**是薄殼與引擎之間公開介面的整數版號；**最低介面版**是引擎仍支援的最低介面版；**檔案版**是 VK 寫檔時標示資料格式的整數版號。
- 薄殼帶**自描述標頭**（介面版、引擎版、其餘內容的 sha256），引擎重算比對、並與 image 內模板二次比對，不符 → 1 列差異、不動任何檔。
- 薄殼重產只由 `install` 與 `upgrade vendor_kit` 觸發；`sync` 發現不符只回 1 提示 `upgrade vendor_kit`。
- 升引擎分兩段：新引擎換上後停下、以 1 結束要求重跑，後續由新引擎接手。
- 版本號 `X.Y.Z`：同一個 X 內不破壞（舊用法能用、舊資料讀得到、格式只加欄位）；X 要變先公告。
- 主機依賴只有 Docker、Git、just（加平台既有的 POSIX 基本指令）；`docker >= 19.03`（不支援 Podman）、`just >= 1.33.0`。啟動器只准呼叫白名單上的主機命令。

### 出貨與 release

- 工具在 `dist/` 交付出貨內容（`dist/just/<ns>.just` 每檔一個頂層命名空間，`<repo>.just` 必須存在）；**取件**是把工具內容從工具 image 取出寫進 `cache/` 的動作。
- Release 資產：每個支援平台一份 image tar、旁邊一份同名 `.digest`（記正式多架構 index digest）、一份 `SHA256SUMS` 涵蓋其餘資產。
- 離線導入（`add --local`）讀旁檔取得 digest 寫進版本鎖定行，旁檔缺 → 1。已釋出的 image 與 Release 資產永不刪。
- 承諾必須黑箱可驗：可觀察的結果只有結束碼、檔案系統、印出的訊息。本機開發與正式啟動走同一個入口。

### 11 條不變量（跨頁護欄，只用編號與這個短名引用）

1. 使用者寫的內容歸使用者：可以建、要改先問、永不刪、永不覆蓋
2. 一個來源：版本鎖定行只有一份，進 git
3. 自動化只碰不進 git 的東西
4. 永不靜默失敗
5. 主機依賴最小：除平台既有的基本工具外，只需 Docker、Git、just
6. 引擎版本由安裝目錄鎖定；啟動器不判斷 repo 內容的意義
7. 工具 image 只承載交付資料；引擎與工具不互相綁發版
8. 使用者介面極少；recipe 語意固定
9. 對外承諾必須黑箱可驗；本機開發與正式啟動走同一個入口
10. 相容性與演進：同一個 X 內不破壞，X 變動才可能不相容且先公告
11. 正確性不綁單一平台

## 名詞紀律（違反就是規格不合用）

只用上面出現過的詞。**禁止出現這些舊說法：** 專案、專案根、專案檔、動詞、子命令、下游（下游 repo／下游使用者／下游 image）、接入、三方合併、`.version`、`.<repo>/`、tracked 檔、版控檔、簽章、信任來源、導入根、`<name>`。

**禁止出現這些已經不存在的 recipe：** `verify`、`ensure`、`init`、`diff`、`accept`、`rollback`。也不要寫 `--purge`。

注意：`init.toml` 與「範本」**不是**禁用詞，是現行用語。「初始檔」是正確說法，不要寫成「模板檔」。

## 14 頁清單

「來源」是舊圖頁號，只供你判斷該頁涵蓋的題材範圍，**不要逐格照抄舊圖，也不要在輸出裡提到舊圖頁號**。

### 主要架構五頁

- **A1 VK 的承諾與兩個使用情境** — 承諾關係兩方、導入與出貨各承諾什麼、什麼不在承諾範圍內（來源 01–05、09、69–70）
- **A2 系統主要架構與責任邊界** — 使用者／薄殼／啟動器／引擎／工具 image／registry／repo 的連接，誰能解讀規則（來源 06、09–11、14、71、73）
- **A3 安裝目錄、檔案所有權與唯一版本來源** — 哪些檔進 git、哪些可重建、誰擁有、版本真相在哪（來源 06–08、09、56、72、75）
- **A4 共同執行骨架：resolve、apply、進度與恢復** — 時序五步、預檢、原子替換、中斷後怎麼被看出來（來源 08、10–11、57、59、76）
- **A5 相容性、CI 與黑箱驗收邊界** — 介面版區間、零寫入的 `3`、黑箱觀察面、release gate（來源 12–13、58–61、77）

### 重點流程九頁

- **F1 首次導入：`bootstrap.sh` → `install`**（來源 15–22、62–63 共同部分、70）
- **F2 加入工具與日常同步：`add`／`sync`**（來源 23–29、73、77）
- **F3 發現與套用工具新版：`update`／`upgrade`**（來源 30–34、36、55）
- **F4 初始檔升級與衝突重入** — 基準版／目前 repo 檔／新版初始檔三者怎麼併（來源 33–35、56、72、75）
- **F5 升級 VK 引擎與薄殼接手**（來源 37–43、58）
- **F6 本機開發來源：`dev`／`undev`**（來源 44–48、74）
- **F7 解除工具與移除 VK：`remove`／`uninstall`**（來源 49–52）
- **F8 清理本機資源：`prune`**（來源 53–54）
- **F9 出貨、release 與離線導入**（來源 60–68）

## 輸出格式（一字不差照這個形狀，14 頁全部都要）

每頁一個 `## ` 段落，段落底下**恰好四個小節**，順序固定，小節名後面直接接內容行：

```
## A1 VK 的承諾與兩個使用情境

回答: <一句話說這頁回答什麼問題>

泳道: <泳道名 | 泳道名 | ...>   ← 沒有泳道就寫「無」

方塊:
- B1 [方塊型別] 泳道名 | 方塊上的文字（一行，最多 20 字）
- B2 [判斷] 泳道名 | 方塊上的文字
- ...

連線:
- B1 -> B2 | 連線標籤（沒有標籤寫「無」）
- B2 -> B5 | 是
- ...

服務不變量: 1, 4, 8
```

規則：

- `回答:`、`泳道:`、`方塊:`、`連線:`、`服務不變量:` 五個標記一頁一次、缺一不可，名稱一字不差。
- 方塊編號在每頁內從 `B1` 連號，不跨頁重複使用同一個號的語意。
- 方塊型別只用這六種之一：`起點`、`動作`、`判斷`、`資料`、`結束`、`註記`。
- 判斷方塊的出邊必須帶標籤（例如 `是`／`否`／`不符`／`有新版`），且至少兩條。
- 沒有泳道的頁，方塊行的「泳道名」欄寫 `-`。
- 連線只能連同一頁裡列過的方塊編號。
- `服務不變量:` 只寫 1–11 的編號，逗號分隔，至少一個、最多四個。
- 每頁 8–16 個方塊。
- 不要在四個小節之外加說明段落，不要在段落之間加前言或結論。
