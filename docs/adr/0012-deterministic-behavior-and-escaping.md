# 引擎容器內的語言與時區寫死，行尾與跳脫逐處指定

跨平台不一致不會變成紅燈：行尾比對不等價就冒出假的合併衝突，排序隨主機 locale 改變就讓兩台機器對同一份輸入給出不同順序，而結束碼照樣是 `0`（[不變量 11](../contract/02_invariants.md#11-正確性不綁單一平台)）。容器內的環境是 VK 自己造的，主機的 shell、locale 與時區不是。所以引擎 image 裡寫死 `LC_ALL=C.UTF-8` 與 `TZ=UTC`，主機那一側只靠跳脫；行尾與跳脫在每個介面上先定好文法，由產生那一側負責，接收端不猜、不補救。

## Considered Options

- **不固定容器環境，各處用到時自己指定 locale 與時區**：擁有者從一個變成 N 個，漏掉的那一處在開發機上照樣通過（違反[設計原則 P5](../../doc/decisions/design_principles.md#p5-一條規則一個擁有者)）。
- **只認 LF，CRLF 當不同內容**：Windows 端經 git 取得的檔常是 CRLF，會冒出假衝突。
- **導入端把使用者檔的行尾一律改寫成 LF**：動到使用者沒要求改的檔，違反[不變量 1](../contract/02_invariants.md#1-使用者寫的內容歸使用者可以建要改先問永不刪永不覆蓋)。
- **三處用同一種跳脫**：三個接收端的文法本來就不同，硬套一種只會讓其中兩處要在接收端再解一層。
- **時間戳記主機本地時間加時區偏移**：每個讀紀錄的地方都得先正規化才能排序與比對，那一步遲早被漏掉。

## Consequences

- locale、時區、行尾、特殊字元四類差異在每個支援平台上有同一個答案；[ADR-0003](0003-baseline-merge-and-line-records.md)、[ADR-0005](0005-run-log-and-event-registry.md)、[ADR-0007](0007-host-thin-layer-and-shell-integrity.md) 引本檔，規則只有一份。
- 引擎內不能用主機 locale 的排序與大小寫規則；要按使用者語言排序的輸出得另外決定。
- 三處跳脫是三套規則，新增一個介面就要指定它的文法。
- 驗收由 [ADR-0011](0011-test-layers-and-ci-matrix.md) 的跨平台矩陣涵蓋；本檔定規則，不定驗法。
- 內部機制（之後搬到實作 issue）：
  - 環境在引擎 image 裡設好，不由啟動器傳入、也不由 recipe 臨場設定。時間戳一律 UTC ISO 8601；排序、比對與大小寫轉換不隨主機改變。
  - 行尾：`dist/` 文字檔一律 LF；append 行比對 CRLF／LF 等價；薄殼 hash 先 CRLF→LF 正規化再算。
  - 跳脫：啟動器傳路徑一律加引號（含空白、`$`、非 ASCII）；引擎回給啟動器的執行計畫裡，自由文字用八進位跳脫；執行紀錄的 argv 與路徑逐項 JSON 跳脫。
