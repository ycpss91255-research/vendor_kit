# 審閱頁 02：動詞介面表

本頁列 `just vendor_kit <動詞>` 的 11 個動詞、升引擎與 `bootstrap.sh`：只用第 0 頁與第 1 頁的詞，不引用後面的頁；只摘錄規格、不新增決議，出處在文末附錄。審閱方式：逐段看「做什麼／寫哪些檔／結束碼」是否與你認知一致，不一致的寫一句理由。

## 本頁名詞（第 0、1 頁沒有的頁內特有詞）

- 快路徑：`sync` 不起容器的判定——啟動器只比對印記第一行與版本鎖定行、`gen/tools.just` 存在、沒有進度檔、非 CI 模式，全相符就以 0 結束。
- 指紋重驗：兩段式動詞（先算計畫、拉 image、再寫入）在寫入前重算專案狀態的指紋，與計畫不同就不寫、以 1 結束並要求重跑。
- 離線包：release 附的 `docker save` tar 與同名 `.digest` 旁檔（正式 digest）。
- 頁內選項：`--dry-run` 只印會做什麼、不寫（仍拉 image 展開）；`--local <tar>` 用離線包；`--verify` 逐檔驗指紋；`--timeout <秒>` 單次拉 image 上限（預設 300）；`--source <image>` image 名不照慣例時指定；`--no-justfile` 不碰根 justfile 只印指示；`-t <repo>[@<tag>]` 接入時要加的工具（可重複）。

## 所有動詞的通則

- 每次執行第一件事是建執行紀錄；建不了 → 1（失敗、零寫入），沒有關掉它的選項。
- 只准在專案根執行，否則 → 1（需人處理：印出該到哪個目錄）；`sync` 亦無例外，工具 recipe 自動觸發的那次自己先切到專案根。
- 可寫動詞：第一個寫入前建進度檔，成功即刪；開始前遇到未完成交易先恢復再繼續。唯讀動詞（`sync`、`update`）遇到未完成交易印出恢復指令後 → 1，`help` 印出後仍 0。
- 詢問：需要詢問但沒有終端且沒給 `-y` → 1（需人處理：加 `-y` 或在終端執行）；`-y` 只省略詢問，不授權覆蓋、不硬加、不解除 CI 模式；`-y` 與 CI 模式是兩個獨立開關。
- CI 模式：不寫任何進 git 的檔、不查最新版；需改進 git 的檔一律 → 1 印清單（與 `-y` 無關）；仍拉鎖定版 image、仍寫 `cache/`、`gen/`。
- 不帶 `<repo>` 的動詞對每個工具做得完的做完，最後回最需處理的碼（失敗 1 > 衝突 2 > 有新版 2 > 0）。
- 結束碼 3（介面版／檔案版不合）一律零寫入（執行紀錄除外）；網路、認證、不存在 → 1，不得偽裝成 3。

## `install` — `install [-y] [--no-justfile]`（`install <repo>` 誤用 → 1：改用 `add <repo>`）
- 前置：在 git repo 內；上層或下層都沒有 `.vendor_kit/`（有 → 1）；薄殼不存在 = 第一次，存在且自描述首行相符 = 修復，不符 → 1 列差異不動。
- 做什麼：建進度檔 → 建 `.vendor_kit/`（`version.toml` 含引擎的版本鎖定行、`config.toml`、薄殼五檔、空的 `baseline/`、`gen/.stamp`）→ 根 justfile：無 → 建（import 一行加 default）；有 → 問「要加這一行嗎」（`-y` 直接加並印出；已含就不加）→ 根 `.dockerignore`：無 → 建四行；有 → 問後加 → 印出建了／改了什麼 → 刪進度檔。再跑 = 修復：首行相符才重寫薄殼，`config.toml` 缺則建、存在不動。
- 寫哪些檔：VK 檔（版本鎖定行、`config.toml`、薄殼、`gen/.stamp`）；專案檔（根 justfile 一行、根 `.dockerignore` 四行）；進度檔；執行紀錄。不寫 `cache/`。
- 結束碼：0；1 需人處理（非 git repo、巢狀、薄殼被改、需詢問無終端）；1 失敗（寫不進；第一次失敗依進度檔清掉半成品，`log/` 保留）；3 薄殼低於最低介面版或檔案版高於引擎。
- CI 模式：要建或改的檔全是進 git 的 → 1 印清單。

## `uninstall` — `uninstall [-y] [--dry-run]`
- 前置：每個工具都沒有本機覆寫（有 → 1：先 `undev`）；先預檢全部工具，任一不過就整體不動。
- 做什麼：建進度檔 → 逐工具照 `remove` 做 → 只刪確認是 VK 自產（hash 相符）的檔：`version.toml`、`version.local.toml`、薄殼、`gen/`、`cache/`、`baseline/`；被改過的保留並列出；`config.toml` 與基準版副本相同才刪 → 根 justfile 問「要刪這一行嗎」只刪完全相同的行 → 根 `.dockerignore` 問後逐行只刪原文相同的行 → 初始檔不刪只印清單 → `log/` 一律保留（`.vendor_kit/` 只剩它）→ 刪進度檔。
- 寫哪些檔：刪 VK 檔（`log/` 除外）；專案檔只刪自己加的行；進度檔；執行紀錄。
- 結束碼：0；1 需人處理（dev 中、需詢問無終端、任一工具移除失敗 → 中止並列出已完成部分）；1 失敗（寫不進）；3。
- CI 模式：需改進 git 的檔 → 1 印清單。

## `add` — `add <repo>[@<tag>] [--source <image>] [--local <tar>] [-y] [--dry-run] [--timeout <秒>]`
- 前置：`<repo>` 名合法且不是 `vendor_kit`；已接入且完成 → 0 無變更；指定的 `@<tag>` 與版本鎖定行不同 → 1：改用 `upgrade`；私有下游 image 沒憑證又沒指定 `@<tag>` → 1：設 `VENDOR_KIT_REGISTRY_TOKEN` 或指定版本；`--local` 值必須是存在的 `.tar`；初始檔目標撞名、越出專案、指向 `.vendor_kit/`，或 `<ns>` 與其他工具、根 justfile 既有 recipe、`vendor_kit` 撞名 → 1 拒絕。全部在任何寫入前檢查。
- 做什麼：解析（沒指定 → 查最新正式版）→ 拉下游 image 展開 → 指紋重驗 → 寫 `cache/<repo>/` 與印記 → 初始檔：無 → 建；copy 型已存在 → 不納管、只提示（`-y` 也不覆蓋）；append 型已存在 → 問「要加這幾行嗎」（`-y` 免問，印出加了什麼）→ 存基準版與 metadata → 重生 `gen/tools.just` → 最後寫版本鎖定行。`--local`：`docker load` 後由 `.digest` 旁檔取正式 digest 寫版本鎖定行。
- 寫哪些檔：版本鎖定行（最後）；基準版與 metadata；`cache/`；`gen/`（印記、`tools.just`）；初始檔（建或加行）；進度檔（記在 metadata 內）；執行紀錄。
- 結束碼：0；1 需人處理（撞名、拒絕、沒憑證、需詢問無終端）；1 失敗（拉不到或逾時、指紋不同、寫不進）；3。回 1 時版本鎖定行一律未動。
- CI 模式：版本鎖定行、基準版、初始檔都進 git → 1 印清單。

## `remove` — `remove <repo> [-y] [--dry-run]`（不帶 `<repo>` → 印用法、1）
- 前置：本機覆寫中 → 1：先 `undev`；未接入 → 0 加提示。
- 做什麼：算計畫、指紋重驗（不拉 image）→ 建進度檔 → 刪該工具的版本鎖定行、`cache/<repo>/`、基準版、印記、`gen/tools.just` 內該工具的行 → append 過的行問「要刪我們加在 X 的這幾行嗎」只刪原文相同的行（CRLF／LF 視為相同）→ 初始檔不刪只印清單 → 刪進度檔。
- 寫哪些檔：版本鎖定行（刪）；基準版（刪）；`cache/`、`gen/`；專案檔只刪自己加的行；進度檔；執行紀錄。
- 結束碼：0；1 需人處理（dev 中、需詢問無終端）；1 失敗（指紋不同、寫不進）；3。
- CI 模式：需改進 git 的檔 → 1 印清單。

## `update` — `update [<repo>] [--exit-code]`（不帶 = 全部，含引擎）
- 前置：無。
- 做什麼：查 registry 取最新正式版（預發行排除）與版本鎖定行比對、逐一列出；私有工具沒憑證 → 該工具 1 並印「設 `VENDOR_KIT_REGISTRY_TOKEN` 或用 `upgrade <repo>@<tag>`」，其他工具照查再彙總；不可同時宣稱「已是最新」；遇未完成交易印出後 1；末行固定印「套用：just vendor_kit upgrade」。不拉 image、不寫檔。
- 寫哪些檔：只寫執行紀錄。
- 結束碼：0 已列出；1 需人處理（任一工具查不到 → 整體 1，即使另有新版）；`--exit-code` 且有新版 → 2；3。
- CI 模式：不受影響（唯讀，仍查 registry）。

## `upgrade`（工具） — `upgrade [<repo>[@<tag>]] [-y] [--dry-run] [--timeout <秒>]`（不帶 = 全部，含引擎；`@<tag>` 只能配單一 `<repo>`；比現版舊 → warn 仍做）
- 前置（依序）：metadata 記有衝突且檔內仍有衝突標記 → 2 停；版本鎖定行已是新版但基準版仍舊 → 只補到那一版就停、印「另有新版再跑一次」；沒有待補才查最新（或用指定的 `@<tag>`）；沒有基準版 → 1：先 `add`；本機覆寫中 → 1：先 `undev`；不帶 `<repo>` 先完整預檢（含新版新增的 `<ns>`／目標檔撞名）再動任何東西；不帶 `<repo>` 且引擎有新版 → 本次只做升引擎、工具不升。
- 做什麼：拉展開、指紋重驗 → 建進度檔 → 換 `cache/` 與印記 → 初始檔逐檔：你沒改 → 問「換成新版？」；只有你改 → 不動；兩邊都改 → 問「要三方合併嗎？」，衝突留標記；新版新增的檔 → 問「要建 X 嗎」，拒絕就記下、之後不再問（新版再變才再問）；新版刪掉的檔只 warn 不刪；二進位沒改 → 問後換、改過保留；append 行找得到 → 問後替換、找不到 → 不動只印新內容；`-y` 全免問 → 基準版推到新版（衝突仍推；合併結果解析失敗不推）→ 重生 `gen/tools.just` → 最後寫版本鎖定行。`--dry-run` 印會問哪些檔、「你拒絕過」「沒納管」提醒、目標在 CI 設定路徑時醒目警示。
- 寫哪些檔：版本鎖定行；基準版與 metadata；`cache/`；`gen/`；初始檔；進度檔（記在 metadata 內）；執行紀錄。
- 結束碼：0；1 需人處理（沒基準版、dev 中、需詢問無終端）；1 失敗（拉不到、指紋不同、合併程式本身出錯、寫不進）；2 衝突（留標記、印檔名、基準版仍推到新版，解完重跑直到乾淨）；3。多工具彙總照通則。
- CI 模式：不查最新版；需改進 git 的檔 → 1 印清單（與 `-y` 無關）；`--dry-run` 就是契約檢查腳本用的那一步。

## 升引擎 — `upgrade vendor_kit[@<tag>] [-y] [--dry-run]`；`upgrade` 不帶 `<repo>` 遇到引擎新版時，由啟動器自動接手成這個動詞
- 前置：薄殼被改（自描述首行不符）→ 1 列差異不動；有未完成的升引擎進度檔 → 本次就是恢復。
- 做什麼：定目標——指定 `@<tag>` → 不查 registry；CI 模式且沒指定 → 不查、目標 = 現版；其餘 → 查最新。目標 ≠ 現版：建進度檔 → 改引擎的版本鎖定行 → 啟動器改用新引擎再跑一次 → 新引擎重產薄殼五檔與 `gen/.stamp` → `config.toml` 缺則建、有則三方合併（問）→ 刪進度檔 → 1 印「已升級引擎，請 commit `.vendor_kit/` 並再跑原指令」。目標 = 現版：薄殼相符 → 0 無變更；不符 → 用現引擎重產 → 同上 1。降版：目標引擎能無損讀現有檔（比介面版／檔案版）才做，否則改任何檔前 3、印「請 git revert」。
- 寫哪些檔：引擎那行版本鎖定行；薄殼五檔；`gen/.stamp`；`config.toml` 與它的基準版副本；進度檔；執行紀錄。
- 結束碼：0 無變更；1 需人處理（重產完成要 commit 再跑；薄殼被改；版本鎖定行已改但新引擎拉不到或重產失敗 → 印「排除錯誤後再跑升引擎」）；1 失敗（第一行未變時的重產失敗）；3 降版無法無損讀（零寫入）。
- CI 模式：沒指定 `@<tag>` 就不查 registry；需改進 git 的檔（薄殼、版本鎖定行）→ 1 印清單。

## `dev` — `dev <repo> -p <dir>`／`dev vendor_kit -i <tag>`（`-i` 只能 tag、不能 digest）
- 前置：工具已在版本鎖定行（否 → 1）；`<dir>/dist/init.toml` 存在（缺 → 1）；CI 模式拒絕；`-i` 的引擎介面版／檔案版較舊 → 允許，但禁止用它重產薄殼。
- 做什麼：寫本機覆寫；工具：`cache/<repo>/` 改成指向 `<dir>/dist` 的 symlink、印記第一行記 `path:<dir>`；引擎：記 tag 與 image ID，之後啟動器只驗 ID、不拉。單段、不拉 image。
- 寫哪些檔：`version.local.toml`；`cache/`（symlink）；印記；執行紀錄。不建進度檔。
- 結束碼：0；1 需人處理（不在版本鎖定行、缺 `init.toml`、CI 模式）；3。
- CI 模式：拒絕 → 1。

## `undev` — `undev <repo>`／`undev vendor_kit`
- 前置：未啟用 → 0 加提示。
- 做什麼：建進度檔（記要撤的行）→ 撤本機覆寫那一行（撤的是最後一個 → 刪整個 `version.local.toml`）→ 依版本鎖定行重新拉展開 `cache/`（`undev vendor_kit` 不展開）→ 刪進度檔。`undev vendor_kit` 後下次 `sync` 發現 `gen/.stamp` ≠ 引擎版本只提示升引擎、不重寫。
- 寫哪些檔：`version.local.toml`；`cache/`；印記；進度檔；執行紀錄。
- 結束碼：0；1 失敗（拉不到、寫不進；保留可恢復狀態）；3。
- CI 模式：規格未載差異（只寫不進 git 的檔）。

## `sync` — `sync [<repo>] [--verify]`；工具 recipe 執行前自動觸發（那次先切到專案根）
- 前置：快路徑全相符 → 不起容器、0；否則起引擎。遇未完成交易印出後 1、不恢復。
- 做什麼：引擎版本 ≠ `gen/.stamp` 第一行 → 1：跑升引擎，不重寫；每個工具：本機覆寫 → 跳過；`cache/` 缺或印記第一行 ≠ 鎖定 digest → 拉下游 image 重新展開；否則 `--verify` 或 CI 模式 → 逐檔驗指紋，不符 → 重裝並 warn；`gen/tools.just` 缺 → 重生；metadata 沒有完成標記 → 1：跑 `add`；基準版落後版本鎖定行 → 本機 warn 提示 `upgrade`。
- 寫哪些檔：只寫 `cache/`、`gen/`（印記、`tools.just`）、執行紀錄；不改任何進 git 的檔。
- 結束碼：0；1 需人處理（薄殼不符、未完成接入、未完成交易）；1 失敗（拉不到或逾時、寫不進）；3。
- CI 模式：一律逐檔驗指紋；升為 1 的：薄殼不符、基準版落後、未完成接入、任何本機覆寫；仍拉鎖定版 image、仍寫 `cache/`、`gen/`。

## `prune` — `prune [-y] [--dry-run]`
- 前置：無；未恢復的進度檔只列出提示，不刪、不擋。
- 做什麼：引擎列出版本鎖定行與本機覆寫引用的 image（保留清單）→ 啟動器依 VK 標籤列出容器、image、network、volume，扣掉保留清單 → 列出候選 → 問「要刪除以上 vendor_kit 資源嗎？」（`-y` 免問）→ 啟動器逐一刪除 → 引擎建進度檔、刪失效的暫存目錄與已完成交易的殘留、刪進度檔。image 只刪帶標籤且本專案未引用者（其他專案的引用不可知，先 `--dry-run` 看）。執行紀錄的保留清理不屬於 `prune`。
- 寫哪些檔：暫存與進度檔；docker 資源；執行紀錄。不碰進 git 的檔。
- 結束碼：0；1 需人處理（需詢問無終端）；1 失敗（磁碟滿到執行紀錄都寫不進）；3。
- CI 模式：規格未載差異。

## `help` — `help`（別名 `h`）
- 前置：無；不觸網、不安裝、除未完成交易外不偵測任何狀態。
- 做什麼：印命名空間層說明，明寫「已接入的專案跑 sync，不是 install」；遇未完成交易印出恢復指令但仍 0。
- 寫哪些檔：只寫執行紀錄。
- 結束碼：0；1 只在執行紀錄寫不進（失敗）。
- CI 模式：無差異。

## `bootstrap.sh`（第一次接入的啟動器） — `sh bootstrap.sh [-t <repo>[@<tag>]]… [-y] [--local <image tag／tar>] [--timeout <秒>] [-h]`
- 前置：在 git repo 內（否 → 1：先 `git init`）；just ≥ 1.33.0（不足 → 1 印下載與安裝指令）；專案已有 `version.toml` → 用那一行的引擎（拉不到就失敗、不退回內嵌）；只有第一次才用腳本內嵌的引擎版本；最低介面版檢查。
- 做什麼：建 `log/bootstrap/` 寫執行紀錄 → 本機有引擎 image 就不拉、否則拉 → 引擎跑 `install`（失敗 → 依進度檔清半成品、`log/` 保留、印出紀錄位置）→ 逐個 `-t` 依序跑 `add`，任一非 0 → 立即中止、整體 1、列出已完成與未處理（已完成的保留）。`--local`：tar → `docker load` 後由 `.digest` 旁檔取正式 digest；tag → 只驗本機 image ID、記成本機覆寫。`-y` 轉給 `install`、`add`。再跑 = 修復（呼叫 `install`）。
- 寫哪些檔：經 `install`、`add` 寫的全部；`--local` 時 `version.local.toml`（`install` 成功後才寫）；執行紀錄。
- 結束碼：0；1 需人處理（非 git repo、just 太舊、需詢問無終端）；1 失敗（拉不到、`install` 失敗不留半成品、任一 `add` 失敗）；3。
- CI 模式：同 `install`、`add`。

## 本頁待拍板

規格（spec）與討論紀錄（grilling）仍有出入、或兩邊都沒寫清楚的點，列出不取捨：

1. CI 模式定義「不查最新版」與 `update`「不受 CI 模式影響、仍查 registry」並存：第 0 頁的定義寫的是全稱，規格另給 `update` 例外——要在定義加「`update` 除外」，還是 `update` 在 CI 模式也不查？
2. 驗收要在 GitHub Actions 跑完整流程（`install` → `add` → `upgrade` → …），而 Actions 預設 `CI=true`：依 CI 模式規則 `add`／`upgrade` 需改進 git 的檔一律 1。規格沒寫驗收如何處理（清掉 `CI`？另設變數？）。
3. `install`、`uninstall`、`undev`、`prune` 在 CI 模式下的行為，規格只靠通則、討論紀錄沒提；`dev` 明寫拒絕。要不要逐動詞寫死？
4. `prune` 保留清單：討論紀錄寫「清 `version.toml` 未引用者」，規格把本機覆寫（`version.local.toml`）引用的 image 也列入保留。
5. 引擎內「拉 image 展開」的名字：討論紀錄第 1 頁改名 fetch、codex 建議 materialize；規格內部子命令用 materialize，第 0 頁模組名用「取件 `fetch`」。內部名不對外，但兩份文件要對齊。
6. 第 0 頁 `update` 寫「不寫任何檔」，規格與本頁為「只寫執行紀錄」（`help` 那條第 0 頁有寫例外，`update` 沒有）。
