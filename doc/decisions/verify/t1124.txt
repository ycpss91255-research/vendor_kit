Add tag ruleset: require CI for v* tags
## Context

Org-wide audit (2026-09-06) found that **all repos have zero tag rulesets**.
Branch protection requires CI to pass before merging to `main`, but tags
have no protection — anyone with push access can tag an untested commit
and trigger a release workflow.

`omniverse_web_viewer` has been patched as the reference implementation.

## What to do

Add a **tag ruleset** via **Settings → Rules → Rulesets → New tag ruleset**:

| Field | Value |
|---|---|
| Ruleset Name | `Require CI for release tags` |
| Enforcement | `Active` |
| Target tags | Include by pattern: `v*` |
| Restrict deletions | checked |
| Require status checks to pass | see below |
| Block force pushes | checked |

**Required status check** for this repo: `ci-rollup`

## Naming convention

The ruleset name **must** be `Require CI for release tags` across all repos
(aligned with the org-wide standard established on `omniverse_web_viewer`).

## Reference

- `omniverse_web_viewer` ruleset: https://github.com/ycpss91255-docker/omniverse_web_viewer/rules/22380777
- The required status check name matches the one already configured in
  branch protection for `main`.

## Known limitation

Tag rulesets verify "CI passed on this commit" but NOT "this commit is on
`main`". A commit that passed CI via a PR but was never merged could still
be tagged. Mitigation (tracked separately): add a `verify-tag-on-main`
job in the release workflow.

Applied via API (`POST /repos/ycpss91255-docker/base/rulesets`), matching the reference implementation on `omniverse_web_viewer`.

**Tag ruleset created:** https://github.com/ycpss91255-docker/base/rules/22411486

- Enforcement: `active`
- Target tags: `refs/tags/v*`
- Rules: restrict deletions, block force pushes (non-fast-forward), require status checks to pass (enforced on tag creation)
- Required status check: `ci-rollup` (GitHub Actions, integration_id 15368) — matches this repo's `main` branch protection

**Known limitation (unchanged, tracked separately):** a tag ruleset verifies "CI passed on this commit" but not "this commit is on `main`". The `verify-tag-on-main` mitigation noted in the issue is not addressed by this change.

Closing as done.
