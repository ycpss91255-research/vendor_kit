test: fixtures named setup.toml contain INI, so their assertions were never exercised (refs #1127)
Part of #1127 (TOML config format unification epic). Surfaced by #1162.

## Background

#1162 fixed two defects that had been covering for each other:
`dockerfile/toml_bridge.py`'s `--merge` mode exited 1 unconditionally
after a botched merge, and `_conf_load_layers` in
`dist/script/docker/lib/conf.sh` read the bridge's output through a
process substitution, which put the exit status out of reach, and
returned 0 regardless. Together they turned a total config-load failure
into "empty config handle, every value falls back to its default" --
silently.

That silence hid two things. This issue is the first.

## The problem

A large number of test fixtures are named `setup.toml` but contain INI:
bare `key = value` with unquoted string values, bare `[section]`
headers, and `mount_1 = ...` style numbered keys instead of
`[[volumes]]`. With the bridge fixed, these make it report

```
toml-bridge: <fixture>/setup.toml: Invalid value
```

Before the fix they passed only because the swallowed error left an
empty handle and every value fell back to exactly the default the test
asserted. So these tests were not testing what their names claim.

A test that passes because an error was swallowed is worse than a
failing one. A failing test tells you something. A test green for this
reason tells you a path is guarded when nothing is guarding it.

## Measurement (static, the full suite was not run)

Measured on the `feat/toml-config-unification` branch. Every fixture
body written to a `setup.toml` was extracted and fed to a TOML parser
(shell variable references substituted with a placeholder first):

- heredoc form (`cat > .../setup.toml <<EOF`): 175 fixtures, of which
  **126 are not valid TOML**.
- `printf` form (`printf '[section]\nkey = value\n' > .../setup.toml`):
  36 fixtures, of which **26 are not valid TOML**.

## Why 152 is much larger than the count of newly-red tests

Not every fixture reaches the bridge. `_parse_stage_sections`, for
instance, scans text for `[stage:...]` headers and never parses values,
so the INI fixtures in `unit/stage_spec.bats` do not turn red on its
account. The failure count is "the subset that routes through the
bridge today"; 152 is the whole of the debt where a file named `.toml`
holds INI. The gap narrows as D5 (#1134) and D6 (#1135) move
`compose_emit.sh` / `env_emit.sh` onto TOML.

## Requirement for the fix

The migration must not simply rewrite the fixture bodies into valid
TOML. Each one needs its asserted values re-derived: some tests assert
the schema default rather than the value their fixture configures, and
once the fixture parses they will start receiving the configured value.
The assertion has to be changed to test what the test's name claims.
Go through them one at a time; do not batch-`sed` this.

## Acceptance criteria

- [ ] Every fixture body written to a `*.toml` path parses as TOML
- [ ] For each touched test, the asserted value is re-derived rather
      than carried over from the default it happened to match
- [ ] A lint or test catches "file named `.toml`, body is not TOML" in
      CI, so the next one is caught at the gate rather than by the next
      person who trips on it
