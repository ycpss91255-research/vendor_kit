fix(init): the rollback does not know about the smoke tree #1045 moves
## Context

`_init_existing_repo()` in `dist/script/base/init.sh` runs the resync under a
rollback bracket: `_init_arm_rollback` snapshots every root named by
`_init_protected_paths`, and a non-zero exit restores exactly those roots.
The function's own header calls that list "every repo-root-relative path the
existing-repo resync can create, rewrite or delete".

#1045 (9d65f10e) added a new mutation to that sequence,
`_migrate_smoke_tree` (`dist/script/docker/lib/smoke_migrate.sh`), which
moves `test/smoke/*` into `test/bats/smoke/shared/` and seeds
`test/bats/smoke/{devel-test,runtime-test}/.gitkeep`.

## Problem

Neither `test/smoke` nor `test/bats/smoke` is in `_init_protected_paths`, so
neither root is snapshotted and neither is restored.

`_migrate_smoke_tree` runs immediately before `_migrate_dockerfile`. If the
Dockerfile migration fails, the rollback puts the Dockerfile back at its old
`COPY test/smoke/ ...` spelling while the smoke tree stays moved. The repo is
left with a COPY naming a directory that no longer exists, and the next build
dies with `COPY source not found`.

That is precisely the failure `_migrate_smoke_tree`'s own coupling guard
declines the migration to avoid. The guard covers the forward path; the
rollback path reintroduces the same broken state from the other direction.

Second, related defect: the invariant is supposed to be guarded by
`test/bats/unit/init_spec.bats`, `@test "_init_protected_paths: covers every
root the resync writes into (#937)"`. Its body only asserts six hardcoded
lines (`Dockerfile`, `script`, `config`, `.gitignore`, `.dockerignore`,
`justfile`). A test that restates a subset of the list cannot detect a NEW
mutation whose root is absent from it, which is why it stayed green through
#1045. The test is vacuous with respect to the invariant its name claims.

## Proposal

1. Add the smoke-tree roots to `_init_protected_paths`, in the file's
   existing grouped-comment style. Both roots: the migration deletes from
   `test/smoke` and writes into `test/bats/smoke`, and a rollback that
   restores only one half leaves the same mismatched pair.
2. Replace the hardcoded assertion with one derived from behaviour: run a
   real resync against a real consumer fixture seeded with the legacy
   shapes, diff the tree before and after, and assert every path the resync
   created, deleted or rewrote lies under some protected root. Modelled on
   `test/bats/integration/init_installed_paths_spec.bats`, which already
   uses that technique for the installed-paths manifest.
3. Add a regression test that a rollback taken after `_migrate_smoke_tree`
   puts the flat smoke tree back and removes what the migration created.

## Acceptance criteria

- `test/smoke` and `test/bats/smoke` appear in `_init_protected_paths`, in a
  comment group naming the mutation that puts them there.
- A behaviour-derived spec fails when a resync mutation touches a root that
  `_init_protected_paths` does not name, with no path list restated in the
  spec.
- A spec asserts that `_init_snapshot` -> `_migrate_smoke_tree` ->
  `_init_restore_tree` leaves `test/smoke/` exactly as it was and
  `test/bats/smoke/` gone.
- Doc catalogue counts regenerated; changelog `### Fixed` entry added.

## Out of scope

- Any change to `_migrate_smoke_tree`'s own forward behaviour or its
  Dockerfile coupling guard.
- The index residue the migration's `git add -A -- test/smoke
  test/bats/smoke` leaves staged after a rollback. `_init_restore_index`
  only re-adds canonical gitignore entries the resync removed; it does not
  unstage what the migration added. The working tree is correct after this
  fix; the staged rename is cosmetic and is left for separate triage.
- Any release tag or downstream fanout.
