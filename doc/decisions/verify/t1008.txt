fix(docker): Dockerfile.test-tools has no Alpine mirror override, so the gate image is unbuildable where dl-cdn is blocked
## What happened

A `just docker build --target test-tools` run failed at the lint-tools stage:

```
WARNING: fetching https://dl-cdn.alpinelinux.org/alpine/v3.21/main: Permission denied
ERROR: unable to select packages: curl (no such package)
exit 2
```

after a 240-second stall. The retry built clean, so the substance of the tree
was never the problem -- the CDN was.

**The failure does not read as a network failure.** An unreachable index reads
as an empty one, so apk reports that the package list does not contain `curl`
rather than that it could not fetch the list. The first response to this
message is to go looking for a packaging mistake that does not exist.

## The gap

`dockerfile/Dockerfile.test-tools` has no mirror override. Base already ships
this knob for the other two distributions -- `dist/dockerfile/Dockerfile`
carries `APT_MIRROR_DEBIAN` and `APT_MIRROR_UBUNTU:212` -- but Alpine has
none, so `Dockerfile.test-tools` is unbuildable wherever `dl-cdn` is blocked
and nothing can be done about it from the command line.

That matters because `test-tools` is the image the whole local gate runs
inside. A host that cannot build it cannot run `just test`.

## The host this was measured on

The general internet is reachable; two specific hostnames are not, both
timing out at TCP connect with DNS resolving normally, and it reproduces with
the sandbox disabled and no proxy variables set:

| host | result |
|---|---|
| `pypi.org`, `github.com` | 200 |
| `mirrors.edge.kernel.org`, `uk.alpinelinux.org`, `mirror.leaseweb.com` | 200 |
| `dl-cdn.alpinelinux.org` | **timeout** (IPv4 and IPv6) |
| `deb.debian.org` | **timeout** |

The Debian half is already known: kcov coverage needs
`APT_MIRROR_DEBIAN=cloudfront.debian.net` here for exactly this reason. What
is new is that the same block covers Alpine's CDN.

## Proposed fix

`APK_MIRROR`, the Alpine spelling of the `APT_MIRROR_*` args already in the
tree.

- Default stays `dl-cdn.alpinelinux.org`, so a machine that can reach it sees
  no change and the upstream host keeps being named in exactly one place.
- Skip the rewrite entirely when the arg equals the default, rather than
  running a `sed` that replaces the host with itself.
- Forward the build arg from the build path only when the caller set one.

The sibling change for the harness image is
ycpss91255-docker/docker_harness#291, where the same knob took the image from
"fails at apk" to a full green gate on this host.

## Also worth deciding

Whether the 240-second stall should be bounded. Four minutes of silence
before a misleading error is most of the cost of diagnosing this; an apk
timeout that fails in 20 seconds saying it could not reach the index would be
strictly more useful than one that waits and then lies.
