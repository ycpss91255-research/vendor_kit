fix(test): CRLF disarms the errexit-bang backslash continuation and its splice
## Context

Found while closing the round-four review of #956 (branch
`fix/956-upgrade-robustness`). The round-three verifier named it as an
undisclosed defect; the round-four scope was three other findings, so it
is filed rather than fixed, and disclosed in the driver header under
"WHAT IS NOT MODELLED".

## Problem

`_errexit_bang_scan_file` in `script/test/drivers/errexit_bang.sh` reads
physical lines with `IFS= read -r`, which keeps a `\r` on a CRLF file. A
trailing backslash then escapes the CARRIAGE RETURN rather than the
newline, so the scan never sees the line-continuation and reads one
statement as two.

Mostly that OVER-reports: the statement is judged short and the position
rule fires on the wrong line. But the backslash SPLICE added while
closing #956 is lost with it, and that turns one shape into a silent
MISS.

LF (correct, reported today):

```
@test "x" {
  ! grep -q A\
#b f; true
}
```

bash splices `A` and `#b` into the single word `A#b`, so the `#` is data
and the `; true` behind it is a live hand-off.

The byte-identical file with CRLF endings is CLEAN: the `\` escapes the
`\r`, the statement is judged at its own line, the `#b f; true` line is
read as a comment line that opens no statement, and the statement is
then the body's last, so neither rule fires.

Every `*.bats` in this tree is LF today, so this is latent, not live.

## Proposal

- Strip one trailing `\r` per line at the top of the read loop
  (`_line="${_line%$'\r'}"`), with a red spec that fails for the reason
  above.
- Or decide a CRLF `*.bats` is not a file this lint accepts and have the
  population check reject it. bats itself is not reliable on CRLF
  bodies, so rejecting may be the more honest answer.

## Acceptance criteria

- [ ] The CRLF twin of the LF fixture above gets the same verdict as the
      LF one, or is refused with a message naming the line endings.
- [ ] A spec pins whichever behaviour is chosen.

## Out of scope

CRLF handling in any other driver or in the shipped `dist/` scripts.
