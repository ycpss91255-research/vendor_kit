## base's own directory layout is recorded nowhere and checked by nothing

Measured:

- `doc/PRD.md` has 11 invariants; none is about where things live. The nearest,
  invariant 8, covers `config/<component>/` only.
- ADR-00000006 freezes `.base/` interior paths -- the downstream protocol, not
  base's own tree.
- `CONTEXT.md` has Domain / Schema / Logging / Architecture-seams sections and
  **no directory section**.
- `check-claude-md-tree.sh` exists in docker_harness and audits a markdown tree
  listing against the filesystem. `grep -rn 'tree-check\|check-claude-md-tree'`
  over base's `script/` and `.github/` returns **nothing** -- base does not use
  it.

So "why is `compose.yaml` at the root", "why does `dist/test/bats/smoke/` have
its own directory", "what may go in `script/` versus `dist/script/`" have no
answer to point at. Two of those were asked on 2026-09-05; answering them took
an audit each. ADR-00000035 records those two answers; it does not establish
the rule.

## The constraint that shapes the fix

The repo is in rapid iteration. A layout record that **enumerates** directories
costs an edit every time one is added -- and worse, it collides. Measured today
while merging `fix/1021-1024-shared-numbers`: `CONTEXT.md` conflicted because it
lists `script/`'s children by name and two branches each added one.

```
ours   : `script/test`, `script/release`, `script/adr` (real directories, no
theirs : `script/test`, `script/release`, `script/watch` (real directories, no
```

Neither branch did anything wrong. The listing is what made it a conflict. Any
enumerated layout record reproduces this on every new directory, which during
rapid iteration is often.

## Direction: state the OWNERSHIP RULE, and derive the check

Pin the property, not the listing -- the same shape base#1060 settled for the
job count and base#1021/#1024 for the shared numbers.

The rule that would answer all three questions above without naming a single
directory:

- **`dist/**` ships**: it is the subtree a downstream repo receives. Adding a
  directory here adds it to every consumer.
- **`script/**` is base's own**: tooling that never leaves this repo. Adding a
  directory here is free.
- **The repo root** holds what a tool discovers by convention and cannot be
  told to look elsewhere without cost -- `compose.yaml` (Compose derives the
  project name from the config file's directory), `justfile`, `Dockerfile`.

Written that way, `script/watch/` needs no edit: it lands under an existing
rule.

**And the check should be derived, not a second listing.**
`init.sh --list-installed-paths` already publishes what base installs into a
consumer. So "everything under `dist/` reaches a consumer, nothing under
`script/` does" is a claim that can be RUN -- compare the installed-path set
against the tree -- rather than an assertion someone maintains. That is the
same technique `init_installed_paths_spec.bats` already uses.

Worth deciding while building it:

- **Where the rule lives.** PRD reads better than an ADR: an ADR records "we
  chose this among alternatives at a point in time", and a layout rule is a
  standing property used to adjudicate the NEXT directory. But invariant 6
  (base is a subtree) may be the right home for the `dist/` half rather than a
  new invariant.
- **What the check refuses.** A new top-level directory that fits no rule
  should FAIL, naming the rule it does not fit -- otherwise the rule decays
  the first time someone adds one and nothing objects.
- **Whether CONTEXT.md's enumerated `script/` list survives.** It is the thing
  that collided. If the rule is stated, the enumeration is redundant prose that
  will conflict again; if it is kept for readability, it needs the same
  treatment as any derived figure.

## Cost of not doing it

The layout is currently held in file-local comments. That is why the two
questions on 2026-09-05 cost an audit each rather than a link, and why the
ADR index carried two rows numbered 00000030 for weeks with the numbering lint
reporting clean.

Refs ADR-00000035, refs ADR-00000006, refs #1021, refs #1060.
