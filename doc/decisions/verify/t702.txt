fix(wrappers): bare-read EOF crash in prune --volumes + build --reset-conf prompts (unfixed #700 siblings) + conf mv-failure cleanup
## Source
Independent final review after the #698-#700 strengthened audit round. The #700 fix closed the bare-`read` EOF crash for prune's image / worktree-orphans prompts but TWO siblings of the same class remain unfixed and untested.

## Findings

### [high] bare-`read` EOF crash -- 2 unfixed siblings
- `downstream/script/docker/wrapper/prune.sh:588` (`--volumes` confirm prompt) and `downstream/script/docker/wrapper/build.sh:385` (`--reset-conf` confirm prompt) both use a bare `read -r _reply` while the file runs `set -euo pipefail` with no `set +e` around it.
- On closed/non-tty stdin (pipe, CI, `prune --volumes </dev/null`), `read` returns non-zero at EOF and `set -e` aborts ON THAT LINE -- the `case` that maps an empty reply to a clean abort is never reached, so the user gets no `volume_aborted` / `[build] aborted.` diagnostic and a confusing exit code. Same class as the prune image/worktree prompts fixed in #700.
- Test gap that hid it: `prune_sh_spec.bats:160` tests `--volumes` only with `echo n |` (a newline -> `read` succeeds), never closed-stdin EOF; `build_sh_spec.bats` `--reset-conf` tests all use `--yes` / no-conf-skip, never the interactive branch.
- Stale comment: `prune_sh_spec.bats:433-436` claims "the volumes prompt already proved the pattern" -- false; volumes neither tests EOF nor is fixed.
- The robust pattern already exists in the codebase: `setup.sh:4464` / `setup.sh:5031` guard with `[[ ! -t 0 ]]` before `read`; the #700 fix used `read -r _reply || _reply=""`. These two sites use neither.

### [low] conf-writer `mv` failure leaves an orphan temp + no error
- `conf.sh:514` (`_write_setup_conf`) and `conf.sh:601` (`_upsert_conf_value`) end with `mv "${_tmp}" "${_file}"` with NO failure handling, though the comment (conf.sh:511-513) claims a failed `mv` is surfaced rather than leaving a stray temp. On a failed `mv` (e.g. read-only mount) the `setup.conf.XXXXXX` temp is left behind and only the caller's `set -e` propagates, with no actionable message. (Data is not lost -- much milder than the truncate bug #700 fixed -- but contradicts the comment.)

## Acceptance criteria
- [ ] `prune.sh:588` + `build.sh:385` use `read -r _reply || _reply=""` (or a `[[ ! -t 0 ]]` guard); closed-stdin EOF aborts cleanly with the intended diagnostic.
- [ ] EOF (`</dev/null`) specs added for `--volumes` and `--reset-conf`; the stale `prune_sh_spec.bats:433-436` comment corrected.
- [ ] Both conf-writer `mv` calls handle failure (`|| { rm -f "${_tmp}"; _log_err ...; return 1; }`).
- [ ] `just test` green; `just test lint` clean; TEST.md + CHANGELOG synced. Any kcov-fragile new test carries the `COVERAGE=1 && skip` guard (#613).
