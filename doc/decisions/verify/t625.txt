refactor(structure): justfile layering + base/downstream directory split (epic)
## Summary

The `base` repo is the shared subtree template shipped into ~17 downstream
repos (via `git subtree --squash` into each consumer's `.base/`). Today it
has two structural problems:

1. **No extension point for repo-local recipes (#594).** The downstream
   user-facing entry is a single `justfile` (a symlink into
   `.base/script/docker/justfile`) with a fixed recipe set
   (`build/run/exec/stop/prune/setup/setup-tui/upgrade`). A consumer cannot
   add its own recipes: the entry is an auto-flowing symlink owned by base,
   and `just` treats a duplicate recipe name across an import as a **hard
   error** (not a shadow), so there is nowhere safe to put custom recipes.

2. **`base`-own tooling and shipped templates are tangled.** `base` mixes
   its own dev/CI/release tooling and the templates it ships to consumers in
   the same trees (`script/docker`, `config/`, `dockerfile/`, `test/smoke`),
   with no clear line between the two audiences. Anyone reading the repo (or
   an AFK agent) cannot tell what flows into a consumer versus what is
   base-internal.

This epic refactors `base` into a clean **base-own vs shipped** split and
introduces a **layered `just` entry**: docker recipes stay top-level
(`just build`), while everything else is namespaced (`just ci|cd|template`
and per-group `just <group>`). The new repo-owned `script/local/` tree gives
each consumer a committed, never-clobbered place for its own recipe groups,
scaffolded by `just template new <name>`.

## Target layout

### `base` repo (source of truth)

```
base-root/
  downstream/                      # [SHIPS] consumer templates; mirrors a consumer's layout
                                   #         consumer side mounts this as .base/downstream/
    script/
      justfile                     # the entry (no suffix); consumer script/justfile symlinks here
      docker/
        justfile.docker            # docker + meta recipes (build/run/exec/stop/prune/setup/setup-tui/upgrade)
        lib/
        runtime/                   # entrypoint.sh
        wrapper/                   # build.sh run.sh exec.sh stop.sh prune.sh setup.sh setup_tui.sh
      ci/                          # justfile.ci + *.sh
      cd/                          # justfile.cd + *.sh  (skeleton only this epic)
      template/                    # justfile.template, new.sh, skel/(justfile.skel skel.sh)
    config/                        # default config layer (consumer overlays per-file via <repo>/config/)
      docker/setup.conf
      shell/                       # bashrc, bashrc.d/, terminator/, tmux/
    dockerfile/Dockerfile          # consumer Dockerfile template (was Dockerfile.example; .example dropped)
    test/smoke/                    # display_env.bats, script_help.bats, test_helper.bash
    .hadolint.yaml
  script/                          # [BASE-OWN] base's own dev/CI/release tooling
    ci/  justfile.ci  ci.sh  lint_bare_stderr.sh  lint_mixed_test_layout.sh   (root justfile.ci moves here)
    cd/  justfile.cd  *.sh
  test/  unit/  integration/  behavioural/   # [BASE-OWN] base's own tests
  dockerfile/Dockerfile.test-tools           # [BASE-OWN] builds the test-tools image (.test-tools kept: names purpose)
  compose.yaml  .github/  doc/  upgrade.sh  .version  README.md  LICENSE  CONTEXT.md  .codecov.yaml  .gitignore  .dockerignore
```

### Consumer repo (after init)

```
<repo>/
  .base/                  # subtree: whole base repo (downstream/ + base-own script/ + test/)
  justfile                SYMLINK -> script/justfile
  script/
    justfile              SYMLINK -> .base/downstream/script/justfile        (identical to base entry; auto-flows on upgrade)
    docker/   justfile.docker + build.sh run.sh exec.sh stop.sh prune.sh setup.sh setup_tui.sh   ALL SYMLINK -> .base/downstream/script/docker/...
    ci/       justfile.ci  *.sh        SYMLINK -> .base/downstream/script/ci/...
    cd/       justfile.cd  *.sh        SYMLINK -> .base/downstream/script/cd/...
    template/ justfile.template new.sh skel/   SYMLINK -> .base/downstream/script/template/...
    local/                              # REPO-OWNED (seeded once, committed, never clobbered)
      justfile.local      # registry of mod lines; entry imports it (optional); `just template new <name>` appends here
      <name>/ justfile.<name>  <name>.sh   # groups created by `just template new <name>`
  test/smoke/             # shared helpers SYMLINK; repo-specific .bats are REPO-OWNED copies
  Dockerfile compose.yaml config/ ...    # existing structure otherwise unchanged
```

`SYMLINK` = auto-flows from `.base/` on every upgrade (base-owned).
`REPO-OWNED` = seeded once and committed; never clobbered by upgrade.

## Entry file

`.base/downstream/script/justfile` (symlinked as consumer `script/justfile`).
Import/mod paths are **repo-root-relative** (they resolve relative to the
symlink's location, the repo root, not the symlink target's real dir).
Paths are single-quoted.

```just
import  'script/docker/justfile.docker'          # docker recipes TOP-LEVEL (just build/run/...)
mod?    ci        'script/ci/justfile.ci'        # just ci ...
mod?    cd        'script/cd/justfile.cd'        # just cd ...
mod?    template  'script/template/justfile.template'   # just template ... (help + new)
import? 'script/local/justfile.local'            # repo-owned registry of user groups

default:
    @just --list
```

## Decisions

- **Docker recipes are TOP-LEVEL** (`just build`). Everything else is
  namespaced (`just ci|cd|template ...`, `just <group> ...`) to avoid the
  duplicate-recipe-name **hard error** across imports.
- **`script/justfile` is a pure symlink, byte-identical to the base entry**,
  so it auto-flows on upgrade. It is NOT written by new-group. New groups are
  registered by appending `mod` lines to the REPO-OWNED
  `script/local/justfile.local`, which the entry imports optionally.
- **`just template new <name>`** scaffolds
  `script/local/<name>/justfile.<name>` + `<name>.sh` from
  `downstream/script/template/skel/`, and appends a `mod` line to
  `script/local/justfile.local`. Bare `just template` prints help.
- **`base` ships everything under base-root `downstream/`**; base's own
  tooling stays in base-root `script/` + `test/`. The `.base` subtree carries
  both trees; consumer symlinks only ever point into `.base/downstream/`.
- **Naming**: `Dockerfile` (was `Dockerfile.example`; `.example` dropped, the
  `dockerfile/` location disambiguates). `Dockerfile.test-tools` kept (the
  suffix names the image it builds). Group files align to the group name:
  `justfile.<name>` + `<name>.sh`.
- **`ci` and `cd` are SEPARATE folders/namespaces** (not a merged `cicd`).
  CD pipeline content is a future issue; this epic only lays the `cd/`
  skeleton + namespace wiring.
- **Consumer docker wrappers move** from flat `script/*.sh` to
  `script/docker/*.sh`. This affects the Dockerfile COPY (currently globs
  `script/*.sh`), `init.sh` symlink targets, and migration hygiene to remove
  the old flat symlinks.
- **Base CI gate** is the base self-test justfile. It moves from
  `just -f justfile.ci test` to `just -f script/ci/justfile.ci test` (after
  the base-reorg phase). Base CI is serial: each PR must be up-to-date with
  `main`.
- **Strict TDD** throughout: every slice lands red→green→refactor with the
  affected smoke/unit/integration/lint tests.

## ADR-00000011 revision (command model finalised)

After implementing P1.x/P2.x (this epic's #626-633, merged), the command
model was redesigned and locked in **ADR-00000011** (merged via #649),
which amends ADR-00000010 (docker no longer top-level; ci/cd renamed;
init/upgrade leave the root) and re-amends ADR-00000006 Region A.

Key changes vs the original epic:
- **Zero special cases**: every action is a `mod?` namespace; docker is
  no longer top-level (`just build` -> `just docker build`).
- **Action-named namespaces**: ci -> test (all checks incl. lint), cd ->
  release, init/update/upgrade -> a new `base` namespace (apt-aligned
  update/upgrade).
- **Generic test runner** (one runner, the `test/` content decides).
- **base = origin, per-sub symlink** for the whole `script/` tree;
  per-repo content (`test/`, `config/`, `Dockerfile`, `compose.yaml`)
  stays real.
- **min->max coverage** via `--option` narrowing; **--help/--lang at
  every level**; **opt-in completion installer**.
