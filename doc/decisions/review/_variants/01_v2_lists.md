# 變體 2：完全不用表格，使用者做什麼與 VK 承諾什麼各自成段條列

## 兩方與承諾關係

兩方：**使用者** = 會跑 VK 動詞的人。**VK** = 我們，vendor_kit 開發者，維護引擎 image 與薄殼（含啟動器），履行對使用者的承諾。

### 使用者做什麼

導入：把別人做好的工具裝進自己的 repo 用。

- `bootstrap.sh` 第一次把 VK 裝進這個 repo，產生 `.vendor_kit/`。
- `add <repo>` 把工具搬進來，版本鎖成一行。
- `upgrade <repo>` 升版，初始檔做基準版合併；有衝突就手動編輯再重跑。
- 回答詢問，或用 `-y` 一律同意。
- commit 薄殼與版本鎖定行。
- `just <ns> …` 執行工具提供的 recipe。
- 把 VK 提供的 CI 檢查腳本接進自己的 CI。

出貨：把自己做的工具交出去給別人裝。

- 在 repo 裡維護 `dist/`：`files/`、`init.toml`、`just/<ns>.just`。
- 把 `dist/` 打成工具 image 推到 registry。
- `dev`、`undev` 在本機邊改邊測，不必每次推 image。

### VK 承諾什麼

對導入：

- 不刪、不覆蓋 repo 檔。
- 同一行版本鎖定行，在任何機器都裝到同一份內容。
- 升得了：升版只動工具內容與初始檔的合併結果。
- 退得回：`upgrade <repo>@<舊 tag>` 可以退回舊版；版本鎖定行進 git，也可以用 git 還原再 `sync`。
- 失敗必印原因與下一步。
- 主機只需要 `docker`、`git`、`just`，不裝別的東西。

對出貨：

- 照 `dist/` 的格式出貨，VK 就搬得到。
- 只搬檔，不執行、不驗證內容能不能跑。
- 使用者裝到的內容與你推上 registry 的逐檔相同（用 digest 與逐檔指紋確認）。

### VK 對介面的承諾

- 契約只加不改：版本鎖定行、`init.toml`、結束碼這些格式只會加新東西，不會改掉舊的意思。
- 動詞改名時舊名字還能用一段時間，不會一升版就叫不動。
- 要移掉任何東西先公告、分兩步做，不會一次砍掉。
- 引擎內部怎麼寫不算契約，隨時可換——只要上面三條不變。

只打 `just <ns> …` 的人不是「方」：VK 在他背後只做工具 recipe 前的自動 `sync`；`sync` 失敗的訊息要寫清楚該找誰、做什麼，但那是對使用者的承諾內容，不是另一個角色。

例：`ros_env` 這個 repo 出貨一個工具，`robot_a` 這個 repo 導入它；`ros_env` 自己也可以導入別的工具。
