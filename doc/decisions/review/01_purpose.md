# 01 專案目的與承諾

加底線的是 VK 的專有名詞，第一次出現時標記，詳細定義見第 02 頁。

## 要解決的痛點

同一套工具（開發環境設定、共用腳本、初始檔）要送進很多 repo。原本靠 `git subtree` 與 `symlink` 搬，四個問題：

- 工具內容整份進了使用者的 git 歷史，工具的 commit 與使用者的 commit 混在一起。
- 升級是人工作業：沒有一個地方記著「這個 repo 現在用哪一版」，也沒辦法回到某一版。
- 工具的檔與使用者的檔混在一起，分不出哪些能動、哪些是工具要重寫的。
- 工具附的初始檔一旦被使用者改過，下次裝新版就被蓋掉。

所以 VK 要同時做到三件事：搬檔、鎖版、初始檔升版不蓋掉使用者改的。現成工具沒有一個全包，所以自己做，只依賴 [Git](https://git-scm.com/)、[Docker](https://www.docker.com/)、[just](https://github.com/casey/just)。細節見 ADR。

## VK 做的事

- 把工具的交付內容打包成容器 image，推到 registry。
- 每個裝了 VK 的目錄有一份<u>版本鎖定行</u>，記著用哪些工具、哪個版本、哪個引擎，那是唯一的一份；換它就能升版或退版，內容也從它重建。一個 repo 裡可以有好幾個這樣的目錄，各自獨立。
- 把工具內容搬進 repo，不進 git。
- 工具附的<u>初始檔</u>第一次複製給使用者，之後歸使用者；升版做<u>基準版合併</u>，不蓋掉他改過的地方，也永不刪。
- 本機開發：把某個工具（含 VK 自己）指到本機目錄或本機 image。
- 提供一支給 CI 用的檢查腳本：CI 只呼叫它，它回報版本、快取、初始檔是否一致。

支援範圍由實際需求長出來：初始檔支援哪些類型，看工具真的用了什麼，不先列清單。

## VK 不做的事

- 不執行、也不驗證搬來的內容能不能跑。
- 不做工具本身的功能（建置、部署這些是工具自己提供，VK 只負責把它送到 repo 並掛上命名空間）。
- 第一版不做：多個 registry 同時推送、簽章與驗簽、範本變數渲染。
- 不支援 macOS 與 Windows 原生（WSL2 視同 Linux，在範圍內）。
- 不碰 repo 的業務邏輯，也不維護工具與工具之間的相容矩陣。

## 承諾關係

| 名稱 | 是誰 | 承諾關係 |
|---|---|---|
| <u>使用者</u> | 用 VK 管理工具的人：把工具裝進自己的 repo 用（導入），或把自己做的工具交出去給別人裝（出貨） | 被承諾的一方 |
| <u>VK</u> | 我們，vendor_kit 開發者，維護引擎 image 與<u>薄殼</u> | 提出承諾的一方 |

### 使用者的兩個情境

<u>導入</u>：這個 repo 要用別人做好的工具。

- 一次把工具帶進來，原有的內容不動。
- 之後長期由 VK 管：鎖定用哪一版、升版、退版、每次執行前確認裝的跟鎖的一致。
- 工具附的初始檔進來之後就是使用者自己的檔，VK 不再動它，只在升版時幫忙合併。

<u>出貨</u>：這個 repo 自己做了一套工具，要給別的 repo 用。

- 維護要交付的內容，打包推出去。
- 每一版都是不可變的，別的 repo 鎖哪一版就永遠拿到那一版。
- 工具自己的 repo 也可以同時導入別人的工具。

同一個 repo 可以只做其中一件，也可以兩件都做。

只用工具、不碰工具版本的人不在承諾範圍內：VK 只保證工具內容與版本鎖定行一致，工具本身好不好用由做那個工具的人負責。

### VK 對導入的承諾

- 不刪、不覆蓋 repo 檔。
- 同一行版本鎖定行，在任何機器都裝到同一份內容。
- 升得了：repo 檔裡，升版只動初始檔的合併結果。VK 自己的檔會跟著更新：版本鎖定行、基準版、VK 對初始檔的納管紀錄，必要時還有薄殼。
- 退得回：可以退回舊版；版本鎖定行進 git，也可以用 git 還原。
- 失敗必印原因與下一步。
- 主機只需要 Git、Docker、just，不裝別的東西。

### VK 對出貨的承諾

- 照出貨格式準備內容就搬得到。
- 只搬檔，不執行、也不驗證搬來的內容能不能跑。
- 導入端裝到的內容與出貨時推上 registry 的內容逐檔相同（比對 digest 與每個檔的指紋）。

### VK 對相容性的承諾

- 版本號 `X.Y.Z`：
  - Z 變動：修 bug 或小調整，相容。
  - Y 變動：加功能或功能迭代，相容。
  - X 變動：破壞性調整，不保證相容，對外介面可能改變。
- 同一個 X 之內：原本的用法繼續能用，舊資料讀得到，格式只會加新欄位，不改舊欄位的意思。
- X 要變之前先公告，並寫清楚要先升級什麼、要做哪些手動步驟。
- 引擎內部怎麼寫不算契約，隨時可換。
