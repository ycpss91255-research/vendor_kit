## G vendor_kit 契約疑似遺漏（只列事實與 base 是否遇過，不下結論）

1. **git worktree**：`.git` 是檔案，`gitdir:` 指向 `$PWD` 之外 → 容器內 `-v $PWD:/repo` 看不到真 `.git`。base 遇過 worktree 相關：[#893](https://github.com/ycpss91255-docker/base/issues/893) 兩個 worktree 不能同時跑、[#995](https://github.com/ycpss91255-docker/base/issues/995) 468 個殘留 network 來自 worktree 路徑、[#1032](https://github.com/ycpss91255-docker/base/issues/1032)、[#719](https://github.com/ycpss91255-docker/base/issues/719) 用「`.git` 是檔或目錄」區分 worktree。vendor_kit 引擎若只用 `git merge-file` 不需 repo；但若任何步驟在容器內查 tracked 狀態就會受影響。未談。
2. **git submodule 內使用**：同上（`.git` 檔）。base：[#444](https://github.com/ycpss91255-docker/base/issues/444) 只處理 CI checkout 的 submodule；[#1077](https://github.com/ycpss91255-docker/base/issues/1077) 的 consumer 是 `--recurse-submodules` clone。未談。
3. **monorepo／巢狀 repo／子目錄安裝**：base [ADR-6 第四次修正](https://github.com/ycpss91255-docker/base/blob/main/doc/adr/00000006-upgrade-sh-path-contract.md) 寫進第三方 index。vendor_kit：`$PWD` 是否須為 toplevel、一個 repo 能否有多個 `.vendor_kit/`（`justfile_directory()` 指哪）未談。
4. **同機多專案／多 worktree 共用 cache 與 image**：base 曾因共用固定 tag 互踩（[#828](https://github.com/ycpss91255-docker/base/issues/828)、[#887](https://github.com/ycpss91255-docker/base/issues/887)）；vendor_kit 每專案各自 cache/（不共用故不互踩，也不共享下載）；docker image 層由 daemon 共用；拉過的工具 image 無回收動詞（base [#995](https://github.com/ycpss91255-docker/base/issues/995)、[#388](https://github.com/ycpss91255-docker/base/issues/388) 有「垃圾累積」前例）。
5. **離線／間歇網路／proxy／mirror**：base [#1187](https://github.com/ycpss91255-docker/base/issues/1187)、[#1008](https://github.com/ycpss91255-docker/base/issues/1008)、[#164](https://github.com/ycpss91255-docker/base/issues/164)。vendor_kit：`docker pull` 走 daemon 的 proxy；但引擎 `resolve` 在**容器內**直連 registry API（tags/list、token 交換）→ `HTTP_PROXY/HTTPS_PROXY/NO_PROXY`、企業 CA、私有 registry 自簽憑證是否以 `-e`/`-v` 傳入引擎未談；`--local tar` 只覆蓋 bootstrap/add，`upgrade` 離線路徑未談。
6. **時區／locale／語言**：base [#210](https://github.com/ycpss91255-docker/base/issues/210)（`ENV TZ/LANGUAGE`）、[#103](https://github.com/ycpss91255-docker/base/issues/103)（zh_TW 判成 zh）、[#151](https://github.com/ycpss91255-docker/base/issues/151)（`--lang` 靜默退回英文）、ADR-11 §6 `SETUP_LANG`。vendor_kit：訊息語言、metadata 時戳時區（UTC？）未談。
7. **非 root／任意 uid 容器寫檔、rootless docker、Docker Desktop/WSL2 的 uid 映射與 bind-mount 權限**：base [ADR-24](https://github.com/ycpss91255-docker/base/blob/main/doc/adr/00000024-bake-artifacts-at-opt-not-home.md)、[#1188](https://github.com/ycpss91255-docker/base/issues/1188)（open）、[#1032](https://github.com/ycpss91255-docker/base/issues/1032)。base 無 rootless／Podman／Docker Desktop 紀錄。vendor_kit 定 `-u uid:gid` 與 WSL2 支援，但 rootless 下 `-u` 的映射、`docker cp` 落地檔案擁有者、`/mnt/c` 路徑上的 flock 未談。
8. **SELinux（`:z`/`:Z`）**：base 全庫無任何紀錄（ADR/PRD/issue grep 皆零）。vendor_kit `-v $PWD:/repo` 在 Fedora/RHEL enforcing 下需要 label；未談。
9. **`-t` 指舊版**：base [#916](https://github.com/ycpss91255-docker/base/issues/916)「a hardcoded new path breaks bootstrapping an OLD tag」。vendor_kit：`bootstrap.sh vN -t <舊引擎>`、`upgrade vendor_kit -t <比薄殼舊>` 的薄殼↔引擎相容方向未談（A1 只談向前）。
10. **`.gitattributes`／行尾／權限位**：base [#990](https://github.com/ycpss91255-docker/base/issues/990)。vendor_kit #29 已開；tracked 薄殼的 hash 比對是否忽略 mode bit／CRLF 未寫。
11. **中斷（SIGINT）與逾時**：base [#1015](https://github.com/ycpss91255-docker/base/issues/1015)、[#1014](https://github.com/ycpss91255-docker/base/issues/1014)（無 concurrency/timeouts 宣告）。vendor_kit 進度日誌覆蓋 apply 中斷；啟動器在 `docker pull` 卡住（#1187 的 240 秒）時的逾時未談。
12. **image 基底 EOL 與時間觸發**：base [#1030](https://github.com/ycpss91255-docker/base/issues/1030)（alpine EOL spec 有到期日）。vendor_kit 引擎 image 基底與其 EOL 檢查未談。
13. **同名 package 由別的 repo 先建**、**公開不可逆**：base [#1176](https://github.com/ycpss91255-docker/base/issues/1176)；vendor_kit Q7 只提醒後者。
14. **Renovate 對 `tag@digest` 的更新**：base [#822](https://github.com/ycpss91255-docker/base/issues/822)（Dependabot 看不到自訂 pin）；vendor_kit 需 regex manager 同時更新 tag 與 index digest，範例未寫。
15. **就地升級與全新安裝的收斂**：base [#1057](https://github.com/ycpss91255-docker/base/issues/1057)（open）「is the upgraded repo what a fresh one would be」；vendor_kit 未談。
