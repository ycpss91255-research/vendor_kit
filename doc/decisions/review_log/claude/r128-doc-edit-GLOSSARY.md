## 必改

1. **位置**：GLOSSARY.md 第 196 行「需人處理」。
   **問題**：定義寫「表示這次執行沒有做完」，但 03 第 79 行 `VK0021`（合併衝突）標的是 level `warn`、處置「需人處理」；依 #117 合併衝突屬於「做完但要人接手」（結束碼 `1`），不是沒做完。GLOSSARY 和 03 至少有一邊錯了。
   **建議**：依 #117，需人處理屬於「沒做完」。所以 GLOSSARY 保留「沒有做完」，把 03 `VK0021` 的處置改成「—」，下一步 `git status` 保留（03 第 55 行本來就允許 warn 列下一步）；另一種改法是把 GLOSSARY 的「沒有做完」刪掉，改寫成「VK 知道使用者接下來要做什麼，必附可直接複製的下一步指令」。兩邊要一致。
   **證據**：GLOSSARY.md:196；03_messages.md:79、:20、:53；#117 決議第 1 條。

2. **位置**：GLOSSARY.md 第 196、199 行「需人處理」與「失敗」。
   **問題**：#114 定案「需人處理」「失敗」是同一個處置屬性的兩個值（03 的「處置」欄就是：需人處理／失敗／—）。GLOSSARY 卻把需人處理寫成「診斷的處置屬性」、把失敗寫成「……的結果」，兩者不是同一種東西。另外 03 第 53 行寫「處置是結果的屬性」，GLOSSARY 寫「診斷的處置屬性」，說法也不同。
   **建議**：失敗改成「診斷的處置屬性，表示這次執行沒有做完，而且只能說明原因；不附下一步指令，也不承諾有可直接執行的處置」。03 第 53 行跟著統一成「診斷的屬性」（或 GLOSSARY 統一成「結果的屬性」，兩邊擇一）。
   **證據**：GLOSSARY.md:196、:199；03_messages.md:53、:57；#114 維護者決議第 4 條。

3. **位置**：GLOSSARY.md 第 201 行「警告」。
   **問題**：用自己定義自己：「指出這次執行有警告……的診斷」。第一次看的人還是不知道警告是什麼。這一行也沒講它跟 level `warn` 的關係。
   **建議**：改成「level 為 `warn` 的診斷：指出這次執行有非阻斷的問題，或雖已做完但仍要使用者接手；只要印出警告就不算成功，以結束碼 `1` 結束」。
   **證據**：GLOSSARY.md:201；03_messages.md:20、:45。

4. **位置**：GLOSSARY.md「執行與結果」段（第 170～208 行）。
   **問題**：「診斷」在本檔第 196、201、205 行都有用到，04 第 202 行也用了「正常輸出」，但兩個詞 GLOSSARY 都沒定義。#115 結論的「要改的檔」明列 GLOSSARY「新增『診斷』『正常輸出』」。「診斷」是這一輪新定義的核心詞，沒定義的話，需人處理、警告、原因代碼三條都靠一個未定義的詞。
   **建議**：在「需人處理」前面新增兩條：**診斷**（diagnostic）：VK 印到 stderr、第一行為 `vendor_kit: <level>[VKnnnn]: <中文本文>` 的訊息，含續行；level 只有 `warn`、`error`、`fatal`。**正常輸出**（normal output）：成功時印到 stdout、不加前綴的輸出，例如改了什麼、查詢結果、`-h`／`--help` 的用法。
   **證據**：GLOSSARY.md:196、:201、:205；04_interface.md:202、:204；03_messages.md:33、:45；#115 本題結論「要改的檔／其他」。

5. **位置**：GLOSSARY.md 第 208 行「結束碼」。
   **問題**：寫「`2`（error）表示沒做完，包括需人處理」，讀起來是「需人處理 → `2`」。但 03 的 `VK0007`～`VK0009` 是 fatal 加需人處理，結束碼是 `3`。結束碼看的是 level，不看處置，這一行把兩件事綁在一起了。
   **建議**：改成「`2`（error）表示沒做完，包括用法錯誤，以及處置為需人處理或失敗的 error 診斷；`3`（fatal）只表示版本組合不合，這類診斷也可能是需人處理」。或者明寫「結束碼由診斷的 level 決定，與處置無關」。
   **證據**：GLOSSARY.md:208；03_messages.md:21、:65～67；#114 決議第 2、4 條。

## 建議

1. **位置**：GLOSSARY.md 第 244～245 行「救援路徑」（`just vendor_kit` 不帶指令）。
   **問題**：這裡寫「輸出到 stderr、以結束碼 `2` 結束」，但沒有 `error[VKnnnn]` 診斷。這跟 #115 決議第 1 條「每個非 0 的結束碼都有同 level 的診斷，沒有例外」衝突，也不在 03 第 34 行 stderr 封閉清單裡（這不是用法錯誤後附的用法，除非它本身就算用法錯誤）。04 第 127 行也一樣。
   **建議**：把不帶指令歸為用法錯誤，先印一條 `error[VKnnnn]` 診斷，再印版本與用法，03 補代碼；或者請維護者就 #99 和 #115 的衝突拍板。這會改變對外輸出，所以先確認再改。
   **證據**：GLOSSARY.md:245；04_interface.md:127、:129；03_messages.md:34；#99；#115 決議第 1 條。

2. **位置**：GLOSSARY.md 第 83、208 行（「用法錯誤」）。
   **問題**：「用法錯誤」GLOSSARY 沒有定義。04 第 129 行要求用法錯誤先印 `error` 診斷，但 03 代碼表沒有任何用法錯誤的代碼（包括 tag 格式不合），所以沒有 `VKnnnn` 可以印。
   **建議**：GLOSSARY 補「用法錯誤」條目（或在「診斷」條目中說明），並提醒 03 補代碼（屬 03 的責任）。
   **證據**：GLOSSARY.md:83、:208；04_interface.md:129、:149；03_messages.md:57～80。

3. **位置**：GLOSSARY.md 第 208 行「結束碼」。
   **問題**：`info`／`warn`／`error`／`fatal` 與「level」GLOSSARY 都沒定義，只在括號裡帶過。
   **建議**：放進新增的「診斷」條目，或另立「level」條目：`info`、`warn`、`error`、`fatal` 四級，對應結束碼 `0`～`3`；stderr 診斷不用 `info`。
   **證據**：GLOSSARY.md:208；03_messages.md:17～22、:45。

4. **位置**：GLOSSARY.md 第 207～208 行「結束碼」。
   **問題**：定義寫「VK recipe 結束時回給呼叫方的整數」，但 `bootstrap.sh`（不是 VK recipe）也照這套碼回 `2`（`VK0005`）。
   **建議**：改成「VK recipe 或 `bootstrap.sh` 結束時回給呼叫方的整數」。
   **證據**：GLOSSARY.md:208；03_messages.md:63、:87；04_interface.md:35、:39。

5. **位置**：GLOSSARY.md 第 208 行（易讀性）。
   **問題**：一句話塞了四個碼、多值規則與「成功」的定義，太長。
   **建議**：拆成三句：第一句說整數與 level 的對應；第二句逐碼一小句；第三句「多個結果取最大」。
   **證據**：GLOSSARY.md:208。

6. **位置**：GLOSSARY.md 第 205 行「原因代碼」。
   **問題**：沒講代碼印在哪裡、給誰用。ADR-0005 第 3、16 行已定：同一個代碼寫進執行紀錄的 `vendor_kit.reason_code`。
   **建議**：補半句：「印在診斷第一行的 `[VKnnnn]`，執行紀錄記同一個代碼」。
   **證據**：GLOSSARY.md:205；doc/adr/0005-run-log-and-event-registry.md:3、:16；03_messages.md:45。

7. **位置**：GLOSSARY.md 第 195～208 行（詞條順序）。
   **問題**：「需人處理」「失敗」先用了「診斷」「結束碼」，這兩個詞卻排在後面才定義。
   **建議**：順序改成 診斷 → 原因代碼 → 結束碼 → 警告 → 需人處理 → 失敗。
   **證據**：GLOSSARY.md:195～208。
