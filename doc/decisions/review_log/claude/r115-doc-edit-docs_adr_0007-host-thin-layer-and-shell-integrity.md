## 建議

1. **第 16 行：訊息編號跟前面列的項目順序相反**
   - 問題：句子寫「Docker 版本不足與偵測到 Podman……（訊息 M11、M12）」，但 M11 是 Podman、M12 是 Docker 版本不足（03_messages.md 第 63、64 行）。讀者照順序對，會把兩條對錯。
   - 建議：改成「偵測到 Podman 與 Docker 版本不足：……（[訊息 M11、M12](../contract/03_messages.md#訊息)）」，或把括號裡的順序改成「M12、M11」。
   - 證據：0007 第 16 行；03_messages.md 第 63～64 行。ADR-0004 第 26 行也是同樣的順序，要一起改。

2. **第 31～32 行：沒寫明救援路徑照常寫入**
   - 問題：r114 在 02 第 4 條（第 94 行）與 ADR-0008 第 3 行補上「救援路徑在版本組合不合時仍然可用，照它本來的行為寫入」。本檔第 32 行只說救援路徑「永久可用」，沒說它照常寫入。本檔又是救援路徑的決策出處，只看本檔的人可能以為救援路徑也受零寫入限制。
   - 建議：在第 32 行「永久可用的救援路徑：」後面補「；版本組合不合時仍照本來的行為寫入」。或者把第 31 行最後一句拆出來，改成「零寫入只套在判定不合、回 `3` 的這次執行，不含執行紀錄（[不變量 4](…)）；救援路徑照常寫入」。
   - 證據：02_invariants.md 第 94 行；0008 第 3 行；0007 第 31～32 行。

3. **第 31 行：句子太長**
   - 問題：同一個條目串了四件事：擋下的時機、結束碼與訊息、零寫入的範圍、判定規則在哪裡；最後一句「這裡與不變量 10、ADR-0008 說的『零寫入』，依不變量 4 都不含執行紀錄」還回頭改前面詞的定義。
   - 建議：拆成兩句。第一句寫行為（擋下、回 `3`、M9，判定規則見 ADR-0008）；第二句單獨寫零寫入的範圍（可以跟建議 2 合在一起寫）。
   - 證據：0007 第 31 行。

4. **第 32 行：「`sync` 的不符判定」跟 GLOSSARY 的寫法不一樣**
   - 問題：GLOSSARY 的「救援路徑」詞條寫「`sync` 的版本不符判定」，本檔少了「版本」兩個字。這不是 r114 造成的，但本檔正在列救援路徑的清單，應該跟詞條逐字一致。
   - 建議：改成「`sync` 的版本不符判定」。
   - 證據：GLOSSARY.md 第 240 行；0007 第 32 行。

5. **第 32 行：連到 Q13 的連結沒有錨點**
   - 問題：「[待討論佇列](…/discussion_queue.md) Q13」只連到整份檔。ADR-0008 第 3 行連 Q5 時有帶錨點。
   - 建議：改成連到 `discussion_queue.md#q13-…`，錨點由佇列第 157 行的標題產生。
   - 證據：discussion_queue.md 第 157 行；0008 第 3 行。

6. **第 3、22、31 行：用「新 major」，契約頁用「X」**
   - 問題：02 第 10 條與 03 的 M9 都寫「X 較新的引擎」，GLOSSARY 沒有定義「major」。本檔寫「新 major」，讀者要自己把兩種說法對起來。這不是 _Avoid_ 詞，lint 不會擋。
   - 建議：改成「X 較新的引擎」或「新的 X」，跟 02 第 10 條、03 的 M9 一致。
   - 證據：0007 第 3、22、31 行；03_messages.md 第 61 行；02_invariants.md 第 178 行。
