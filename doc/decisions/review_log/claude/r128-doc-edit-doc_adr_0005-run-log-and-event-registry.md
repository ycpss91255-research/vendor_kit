# r128 審查：doc/adr/0005-run-log-and-event-registry.md

## 必改

1. **位置**：doc/adr/0005-run-log-and-event-registry.md 第 21 行（內部機制第 1 點）「未註冊的事件名都當實作錯誤（FATAL）」
   - **問題**：這一輪 fatal 已定成只限版本組合不合、結束碼 3（#117、#114）。這裡還把「未註冊事件名」標成 FATAL，跟 03 第 22 行（`3` fatal 只限版本組合不合）、GLOSSARY 第 208 行（`3`（fatal）只表示版本組合不合）、ADR-0008 標題對不上。讀者會以為實作錯誤回 3、印 `fatal[...]`。ask 要求「只改跟上面矛盾的地方」，這句就是矛盾的地方，本輪卻沒改。
   - **建議**：改成「未註冊的事件名都當實作錯誤，立即停下、以失敗結束（error，[結束碼 `2`](../contract/03_messages.md#結束碼)）」，不寫 FATAL。
   - **證據**：ADR-0005 第 21 行；03 第 22 行；GLOSSARY 第 208 行；ADR-0008 第 1 行；#117、#114。

2. **位置**：doc/adr/0005-run-log-and-event-registry.md 第 9 行（Considered Options「未註冊的事件名只警告、照樣寫進紀錄」）
   - **問題**：否決理由是「降成警告只會被吞掉」。#117 定案後警告一律回 1，CI 會紅燈；02 第 4 條（第 91、93 行）也寫了印出警告就不算成功。所以「警告會被吞掉」這個前提已經不成立，理由跟 02 第 4 條和 #117 矛盾。
   - **建議**：理由改成不靠「會被吞掉」的說法，例如「未註冊只可能是實作錯誤，使用者沒有下一步可做；警告要指名對象並給下一步（[不變量 4](../contract/02_invariants.md#4-永不靜默失敗)），這裡給不出來，而且照樣寫進紀錄會讓讀取端遇到不認得的名字」。
   - **證據**：ADR-0005 第 9 行；02 第 91、93、107 行；03 第 20、24 行；#117。

## 建議

1. **位置**：第 3 行新增句「每印一條帶原因代碼的 stderr 診斷」
   - **問題**：「帶原因代碼的」這個限定語會讓人以為有些診斷沒有代碼。但 03 第 45、47 行規定每條診斷第一行都是 `vendor_kit: <level>[VKnnnn]: …`，GLOSSARY 第 205 行也說原因代碼是「每條診斷的固定識別碼」。
   - **建議**：改成「每印一條 stderr 診斷」。
   - **證據**：ADR-0005 第 3 行；03 第 45、47 行；GLOSSARY 第 205 行。

2. **位置**：第 3 行（整段）
   - **問題**：第一段本來講「機器可讀輸出只走執行紀錄、事件名封閉」，後面又接上一句很長的 `diagnostic_emitted` 規則加兩個例外，整段變得太長。「唯二例外」的寫法也比較繞。
   - **建議**：第一段只留一句短的「每條 stderr 診斷都對應一筆 `diagnostic_emitted` 紀錄，以 `vendor_kit.reason_code` 對上原因代碼」。兩個例外（主機前置檢查、建不出執行紀錄）移到 Consequences 或內部機制，寫成「以下兩種情況只有 stderr、沒有紀錄：…」。
   - **證據**：ADR-0005 第 3、16、24 行。

3. **位置**：第 16 行，或內部機制
   - **問題**：`diagnostic_emitted` 是新增的事件名。依本 ADR 第 17、21、22 行，它要進真本；啟動器也會印診斷，所以也要進 `log.sh` 的內嵌子集。進子集就是改薄殼檔，既有 repo 要先 `upgrade --engine`。#118 的結論明寫了這點，本檔沒寫，讀者看不出這次新增觸發了第 17 行的限制。
   - **建議**：補一句「`diagnostic_emitted` 同時列入真本與 `log.sh` 內嵌子集，照第 17 行的規則處理」。
   - **證據**：ADR-0005 第 16、17、22 行；#118「實作與測試」段。

4. **位置**：第 24 行「只在 stderr 印訊息」
   - **問題**：03 第 34、45 行與 ADR-0004 第 27 行已經統一叫「診斷」。本檔同一段第 3 行也寫「stderr 診斷」，這裡卻寫「訊息」，前後用詞不一致。
   - **建議**：改成「只在 stderr 印診斷」。
   - **證據**：ADR-0005 第 3、24 行；03 第 34、45 行；ADR-0004 第 27 行。

5. **位置**：第 21 行（跟必改 1 連動）
   - **問題**：未註冊事件名這種實作錯誤也會印 stderr 診斷，但 03 的代碼表（VK0001～VK0022）沒有對應的代碼。照第 3 行「每條診斷都寫 `diagnostic_emitted` 帶原因代碼」，這條診斷會沒有代碼可填。
   - **建議**：在本檔寫明實作錯誤用哪個代碼，或註明「實作錯誤的代碼待 03 補」，並開 issue 追蹤。不要在本檔自行編號。
   - **證據**：ADR-0005 第 3、21 行；03 第 57～80 行。
