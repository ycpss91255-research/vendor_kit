7. **位置**：全部 `message`（CSV 第 2～37 行）。**問題**：英文本文開頭一律大寫、句尾加句點（如 `No command was specified.`、`Unknown command or option: <value>.`）。前綴 `vendor_kit: error[VKnnnn]:` 照的是 rustc 的 `error[E0308]: mismatched types`。rustc 的診斷規範是小寫開頭、句尾不加標點；GNU Coding Standards 也說跟在 `program:` 之後的訊息小寫開頭、不加句點；git 的 `fatal: not a git repository ...` 也一樣。本頁沒有寫理由。**建議**：第一句改成小寫開頭（`just`、`vendor_kit`、`<file>` 這類專有字照原樣），單句訊息的句尾不加句點。多句訊息只改第一個字母，後面的句子照常。03.md、04 的範例一起改。**證據**：GNU Coding Standards §4.4 Formatting Error Messages；rustc-dev-guide「Diagnostics > Diagnostic output style guide」；03_messages.csv:29-36。
8. **位置**：VK0020 `message`（CSV 第 25 行）。**問題**：`it was neither requested again nor applied` 把「詢問」譯成 requested，意思變成「沒有再請求這個版本」。GLOSSARY 的**詢問**是 prompt。**建議**：改成 `Version <tag> of <repo> was previously rejected; not prompting again, and it was not applied.`，或 `...; it was not prompted again or applied.`。**證據**：03_messages.csv:25、GLOSSARY.md「**詢問** (prompt)」。
9. **位置**：message 用到的英文名詞（VK0006、0007、0008、0009、0014、0015、0028、0029）。**問題**：跟 GLOSSARY 的英文名對不上，使用者拿英文訊息查不到名詞表。對照如下：`lock entry`（VK0014、0015）應為 lock version line；`Thin-shell`（VK0006、0009）應為 shell；`installation directory`（VK0028、0029）應為 install directory；`file version`（VK0007、0008）應為 schema version（GLOSSARY「檔案版 (schema version)」）；`File fingerprints`（VK0015）應為 per-file digest；`artifacts were fetched again`（VK0015）應為 fetched，GLOSSARY 沒有 artifact。**建議**：一律改用 GLOSSARY 括號裡的英文名，例如 VK0014 `The baseline for <repo> is behind the lock version line. Run: ...`，VK0015 `Per-file digests in cache/ for <repo> did not match; refetched according to the lock version line.`。**證據**：03_messages.csv:11-14、19、20、33、34；GLOSSARY.md 的英文名清單（版本鎖定行、薄殼、安裝目錄、檔案版、逐檔指紋、取件）。

## 建議

1. **位置**：VK0003 `message`（CSV 第 4 行）。**問題**：其他需人處理的訊息都用 `Run: <指令>` 把可以複製的指令放在句尾（VK0004、0014、0028），只有這一格把指令夾在句中：`Run just vendor_kit upgrade <repo> -y locally; then commit and push.`，複製時容易把 `locally;` 一起帶走。**建議**：改成 `Run locally, then commit and push: just vendor_kit upgrade <repo> -y`。**證據**：03_messages.csv:4、5、19、33。
2. **位置**：VK0004 `message`（CSV 第 5 行）。**問題**：`Import of <repo> is incomplete`。GLOSSARY 的**導入**是 consume，VK0031 的離線導入也譯成 import，兩種意思共用一個字。**建議**：改成 `<repo> is not fully consumed` 之類，或在 GLOSSARY 補上導入在訊息裡的英文譯法，讓兩處一致。**證據**：03_messages.csv:5、36；GLOSSARY.md「**導入** (consume)」。
3. **位置**：VK0015 `message`（CSV 第 20 行）。**問題**：`in the cache/` 多了冠詞，而且 `cache/` 是路徑名。**建議**：寫 `in cache/`。**證據**：03_messages.csv:20。
4. **位置**：`description` 欄。**問題**：內容就是舊的中文本文，含 `請執行：…` 這類祈使句，讀起來像另一份要印的訊息，不像「說明」。03.md:86 只寫了「給人閱讀」。**建議**：03.md 的 `description` 規則補一句「不會印出」，免得有人以為 VK 會依語系改印 description。**證據**：03_messages.md:86、03_messages.csv 第 2 行起的 description 欄。
