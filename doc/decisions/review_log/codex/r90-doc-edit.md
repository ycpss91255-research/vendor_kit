## 必改

1. **位置：README.md 第 3 行**

   - **問題：**「記住每個 repo 用哪一版」把鎖版單位寫成 repo。實際單位是「安裝目錄」；同一個 repo 可以有多個安裝目錄，各自鎖不同版本。
   - **建議：**改成「記住每個安裝目錄用哪一版」。
   - **出處：**02 第 2 條「唯一性的單位是安裝目錄，不是 repo」；`CONTEXT.md`「安裝目錄」「版本鎖定行」。

2. **位置：README.md 第 12 行；03_interface.md 第 22–23 行**

   - **問題：**兩份常用指令清單的 `upgrade` 寫法不一致。README 合成 `upgrade <repo>[@<tag>]` 一行，03 拆成兩行，說明文字也不同。不符合「常用指令兩邊寫法相同」。
   - **建議：**兩邊逐字採用同一組用法與說明；合成或拆開都可以，但必須一致。
   - **出處：**本次已定案要求；02 第 8 條規定 `upgrade` 名稱與語意固定。

3. **位置：03_interface.md 第 51 行，`--dry-run`**

   - **問題：**「不寫任何檔」不正確。執行紀錄不可關閉，而且建立執行紀錄早於其他寫入；`--dry-run` 的明定例外只是不建進度檔，不是連執行紀錄也不寫。
   - **建議：**明確保留執行紀錄例外，例如：「只預覽，不寫 repo 檔或 VK 狀態檔，也不建進度檔；仍會留下執行紀錄。」
   - **出處：**02 第 4 條「可寫 recipe 的時序」第 1、2 點，以及「執行紀錄不可關閉」。

4. **位置：03_interface.md 第 73 行，結束碼 `3`**

   - **問題：**「這種情況不動任何檔」過度擴張。第 4 條只保證不動 repo 檔與 VK 狀態檔；啟動器與引擎的開始事件已寫進執行紀錄。
   - **建議：**改成「不動任何 repo 檔或 VK 狀態檔；執行紀錄除外」。
   - **出處：**02 第 4 條對結束碼 `3` 的「零寫入」定義。

5. **位置：03_interface.md 全文，首見名詞**

   - **問題：**大量 `CONTEXT.md` 專有名詞第一次出現時沒有用 `<ins>`。目前只有第 38 行「安裝目錄」和第 57 行「CI 模式」有標，但「CI 模式」其實已在第 50 行先出現。
   - **建議：**至少補標以下第一次出現處：
     - 第 3 行：使用者、VK、選項、結束碼
     - 第 9 行：repo、命名空間
     - 第 10 行：導入、引擎
     - 第 11 行：初始檔
     - 第 21 行：工具、安裝目錄
     - 第 22 行：鎖定版本
     - 第 44 行：進 git 的檔
     - 第 50 行：`-y`、詢問、CI 模式
     - 第 60 行：本機覆寫
     - 第 73 行：薄殼
   - **出處：**已定案的 03 寫法；`CONTEXT.md` 對應詞條。01 也採相同首見標底線規則。

6. **位置：03_interface.md 第 57、62 行，CI 模式判定**

   - **問題：**正文寫「不是 `0` 或 `false`」，但沒說比較不分大小寫，容易被理解成只有小寫值例外。ADR 明定大小寫不敏感。
   - **建議：**改成「不是 `0` 或 `false`（大小寫不敏感）」。
   - **出處：**ADR-0004 §2；目前第 62 行引用的章節正確，但正文少了一項契約細節。

## 建議

1. **位置：03_interface.md 第 38 行**

   - **問題：**「常用三個」緊接在五行用法後面，第一次看的讀者可能以為數量寫錯；實際上是三個 recipe，其中 `upgrade`、`dev` 各展示兩種形式。
   - **建議：**改成「常用 recipe 三個（上表依參數形式列成五行）」或把同一 recipe 合併成一行。
   - **出處：**02 第 8 條；ADR-0004 §1。

2. **位置：README.md 第 12 行**

   - **問題：**「換成新版；指定 tag 就換成那一版，指定舊 tag 就是退版」在同一句內連續切換三種情況，略繞，也容易讓人疑惑「新版」是否可能指定 tag。
   - **建議：**可縮成「換成新版或指定版本；指定舊 tag 可退版」。
   - **出處：**`CONTEXT.md`「`update`、`upgrade`」；02 第 10 條。

3. **位置：03_interface.md 第 24–25 行**

   - **問題：**參數占位符 `<dir>`、`<image>` 沒有在 `CONTEXT.md` 定義；同表的 `<repo>`、`<tag>` 則有定義，契約表的精確度不一致。
   - **建議：**若它們只是一般參數，在指令表後補一句簡短說明；若是契約名詞，再收入 `CONTEXT.md`。其中 `<image>` 最好說清楚是本機 image 名稱／引用，避免與已定義的「image 引用」混淆。
   - **出處：**`CONTEXT.md` 已定義 `<repo>`、tag、image 引用，但沒有 `<dir>`、`<image>`。

4. **位置：連結，README.md 全文及 03_interface.md 全文**

   - **問題：**未發現問題。所有實際連結都有可讀名稱；README 的 repo 相對路徑存在，03 的 repo 內連結都以 `/` 開頭且目標存在。Docker、Git、just、issue #47 四個外部目標目前均可到達。
   - **建議：**維持現狀。
   - **出處：**逐一解析本機路徑並檢查外部目標；03 未出現 issue 編號，README 的 issue #47 符合既定規則。

5. **位置：03_interface.md 各「出處」**

   - **問題：**除上列 `--dry-run`、結束碼 `3` 和 CI 大小寫問題外，其餘條號配對正確：
     - 入口：02 第 8、9 條及 01「VK 做的事」
     - 指令數量與同大版穩定性：02 第 8、10 條
     - 成對、查套用分離、無害：02 第 3、8 條
     - `-y`、非互動與 `--dry-run`：02 第 1、4 條
     - CI 寫入邊界與本機覆寫：02 第 2、3 條及 ADR-0004 §2
     - 結束碼優先序：02 第 4 條
   - **建議：**條號本身不用調整；修正正文的三處契約落差即可。
   - **出處：**01、02 與 ADR-0004 逐項核對。
