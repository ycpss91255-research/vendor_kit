## 必改

1. **位置：README.md:20、24；03_interface.md「入口」第 18、21 行**  
   **問題：** 下載網址雖與 issue #27 逐字一致，但目前實際請求回傳 `404`，因此對外入口尚不存在。README 的安裝步驟現在不可執行。  
   **建議：** 送審前建立含 `bootstrap.sh` 的 release，並再次驗證 `releases/latest/download/bootstrap.sh` 回傳成功；網址本身不要改。  
   **出處：** issue #27「取得 bootstrap.sh」；實際 HTTP 驗證結果為 404。

2. **位置：03_interface.md「入口」第 18 行**  
   **問題：** 下載網址以裸 URL 出現，不是「有名字的超連結」。其餘 Markdown 連結都有名稱。  
   **建議：** 保留下載網址不變，改成具名連結，例如 `[下載 bootstrap.sh](https://github.com/ycpss91255-research/vendor_kit/releases/latest/download/bootstrap.sh)`。README 第 20 行位於命令範例內，不應改掉命令，但可在正文另補具名下載連結。  
   **出處：** 題定規則「連結要有名字」。

3. **位置：03_interface.md「各指令專用選項」第 66 行**  
   **問題：** 「記錄 digest 的旁檔」是實作機制，而且「旁檔」不在 `CONTEXT.md`；03 對外契約不應展開這項實作細節。另外，ADR-0009 §2 是工具 `add --local` 的 `.digest` 機制；issue #27 講的是 `bootstrap.sh --local` 的引擎離線包，採 `version.local.toml` 的 tag 覆寫，兩者不能被讀成同一套離線規則。  
   **建議：** 03 只留下可觀察行為，例如「離線與線上寫入相同的版本鎖定行；缺少必要的 digest 資訊時以 `1` 結束」，並維持 `[ADR-0009] §2` 出處；不要在此寫「旁檔」。  
   **出處：** ADR-0009 §2；issue #27「規格細節」第 1、5 點；`CONTEXT.md` 無「旁檔」。

4. **位置：03_interface.md「共同選項」第 59 行、「結束碼」第 85 行**  
   **問題：** 使用了 `CONTEXT.md` 沒有定義的「VK 狀態檔」和英文 `warn`。名詞表定義的是「VK 檔」與「警告」。  
   **建議：** 將「VK 狀態檔」改成契約實際指涉的既有名詞，或先在 `CONTEXT.md` 定義其範圍；將 `warn` 改為「警告」。  
   **出處：** `CONTEXT.md`「VK 檔」「警告」；02 第 4 條使用「VK 自己的狀態檔」但沒有建立同名 glossary term。

## 建議

1. **位置：README.md「主機需求」第 9–13 行；03_interface.md「主機需求」第 7–11 行**  
   **問題：** README 與 03 兩處確實逐字一致，但與 ADR-0007 §1 並非逐字一致：文件寫「Docker 19.03 以上」，ADR 寫 ``docker >= 19.03``；文件把所有版本不足概括成「印出安裝指令」，ADR §1 則分別規定 Docker／Podman 與 just 的檢查。02 第 5 條只支持依賴集合，不支持版本下限及失敗行為。  
   **建議：** 若審閱要求「逐字一致」，應明確採 ADR 的表示方式；來源標示可改為 ADR-0007 §1，並把 02 第 5 條只連到「主機只需三項依賴」的敘述。  
   **出處：** ADR-0007 §1；02 第 5 條。

2. **位置：README.md「第一次導入」第 17 行；03_interface.md「入口」第 18 行**  
   **問題：** 兩處語意一致，但不是完整逐字一致：README 是兩句；03 把下載、執行位置、git repo 條件、下載引擎、呼叫 `install`、修復全部塞成一句，第一次閱讀不易切分。  
   **建議：** 03 拆成短句，但保留「在要裝 VK 的那個目錄執行」及「這個目錄必須在某個 git repo 裡」兩個既定表述。  
   **出處：** 02 第 3 條；02 第 8 條；README.md 第 17、24 行。

3. **位置：03_interface.md「指令」第 46 行**  
   **問題：** 一句同時定義八個名詞並接上數量與相容性承諾，資訊密度過高；讀者很難把 `<repo>`、安裝目錄、鎖定版本、版本鎖定行的關係一次讀懂。  
   **建議：** 指令清單保持不動；清單後的名詞說明拆成數句或短列。  
   **出處：** `CONTEXT.md` 對應各名詞；02 第 8、10 條。

4. **位置：03_interface.md「結束碼」第 88 行**  
   **問題：** 「現有薄殼、檔案、引擎的版本組合不合」中的「檔案」範圍不清楚，容易被理解成任意 repo 檔；02 寫法相同，但 `CONTEXT.md` 已有較精確的「檔案版」。  
   **建議：** 若實際指檔案格式版本，改成「薄殼、檔案版與引擎的版本組合不合」。  
   **出處：** 02 第 4 條；`CONTEXT.md`「檔案版」。

5. **位置：兩份文件全部 Markdown 連結**  
   **問題：** 除上述裸下載網址外，沒有發現無名稱的 Markdown 連結；所有本機目標路徑均存在，03 的本機連結也都以 `/` 開頭。外部 Docker、Git、just、issue #27、issue #47 連結均可到達。唯一失效目標是尚不存在的 `bootstrap.sh` release 資產。  
   **建議：** 只需處理下載入口及裸 URL，其他連結不必調整。  
   **出處：** README.md、03_interface.md 全部連結的逐項檢查。

6. **位置：03_interface.md 全文名詞**  
   **問題：** 未發現使用 `CONTEXT.md` 明列的 _Avoid_ 詞。固定指令清單中的名詞先於第 46 行出現，但清單格式已定案，不宜為 `<ins>` 改動 help 文字。  
   **建議：** 維持指令清單原樣；將第 46 行視為正文第一次定義。只處理「旁檔」「VK 狀態檔」「warn」三處。  
   **出處：** `CONTEXT.md` 各 `_Avoid_` 條目；題定規則「指令清單不要動」。
