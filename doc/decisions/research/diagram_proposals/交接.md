## 已經查證過、不要再走一遍的事

- **匯出不用容器**。drawio MCP 的 `export_diagram` 直接寫檔，支援 `.drawio`／`.png`／`.svg`，而且能指定頁、「guaranteed to be the requested page」。先前研究的容器方案整份作廢，理由見 `../agy_drawio_export.md` 的檔頭註記。
- **codex 在 `codex exec` 模式拿不到 drawio MCP**。`codex mcp add drawio` 設定加得進去、`codex mcp list` 顯示 enabled，但實測問它有哪些 drawio 工具，它回「沒有」。原因未查明。所以 codex 要參與畫圖，做法是它出逐格規格、由 Claude 代理照著用 MCP 畫（這一輪就是這樣做的）。
- **穩定鍵是 `<diagram id>`**，不是頁名也不是 index。頁序變動只會讓 index 錯位；頁名一改，檔名跟著變、markdown 引用全斷。現有 77 頁的 id 全在、全唯一。
- **不要用「可編輯 PNG」**。它會把整份文件的 XML 嵌進每一張單頁圖，所以改一頁會讓所有圖檔全部變動。
- **「圖沒變」不能比圖檔位元組**，要比來源內容雜湊，而且要先正規化掉座標與 viewport（`dx`／`dy`），否則每次開圖存檔都會讓每一頁都顯示有改。
- **`lint_pages.py` 是假的綠燈**：有 warn 也固定回 0，掛進 `just test` 擋不住任何東西；它的頁面身份規則綁死舊 77 頁的頁名前綴，重畫之後會靜默變成 no-op 但照樣印綠。
- **`check_terms.py` 掃不到 `.drawio`**：`EXCLUDE_FILES` 裡的 `discussion.drawio` 是死碼，因為 `target_files()` 先做 `if not rel.endswith(".md"): continue`。所以圖上的舊詞現在完全沒有 lint 在擋。

## 名詞紀律（畫圖時最容易踩的）

只用 `CONTEXT.md` 定義的詞。真正該清的舊詞是：專案／專案根／專案檔／動詞／子命令／下游／接入／三方合併／`.version`／`.<repo>/`，加上已經不存在的 recipe 名 `verify`／`ensure`／`init`／`diff`／`accept`。

**`init.toml` 與「範本」不是禁用詞** —— `init.toml` 是 `02_invariants.md` 在用的活檔名，「範本」在 `01_purpose.md` 與 ADR-0001 是正確用法。先前有一份錯的清單把它們列進去，照那份做全域替換會把正確的字改壞。

## 已知的 hook 誤擋

`.claude/hooks/guard.py` 的 codex 檢查會擋掉 `codex exec --help`。`--help` 不會等 stdin，這是誤判，規則要排除 `--help`／`--version` 這類旗標。
