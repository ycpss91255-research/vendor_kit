# 任務：提出 VK 架構／流程圖的頁清單與逐格規格（codex 軌 v2，純文字，不要 XML）

你要產出一份**結構化純文字規格**，之後由別人拿去用 drawio MCP 逐格照著畫。頁清單由你自己決定。

## 硬性限制

- **不要輸出任何 XML、mxGraph、drawio 標籤、程式碼或座標。** 只輸出下面指定格式的純文字。
- 不要修改 repo 裡任何檔，不要跑 git 指令。你的產出就是最後的回覆。
- 全程繁體中文。

## 原則（上一輪就是違反這幾條才失敗，務必遵守）

**1. 素材只能用契約。** 唯一真本是：

- `doc/decisions/review/01_purpose.md`
- `doc/decisions/review/02_invariants.md`
- `CONTEXT.md`
- `doc/adr/0001`–`0012`（`doc/adr/00*.md`）

你可以、也應該自己讀這些檔。**不要讀 `discussion.drawio`，也不要讀 `doc/decisions/research/` 底下任何舊提案或舊規格**（那些是過時的）。契約裡沒寫的分支不要自己發明規則；照最接近契約的解讀畫，不要把「契約沒寫」寫成待決問題或矛盾。

上一輪的教訓：升引擎在 ADR-0007 §5 已定案是**兩段式**——換上新引擎就停下、以 1 結束要求重跑，第二次才由新引擎做事。「一次跑完」是那份 ADR 的 Alternatives 明列否決的方案，畫成一次跑完就是錯的。

**2. 已經寫在文件裡的不要上圖。** 下列內容在 01、02、CONTEXT 已經定稿，圖上重畫一次就是第二份真相：

- 承諾清單、兩個使用情境的說明（01）
- 名詞與定義（CONTEXT）
- 不變量條文（02）
- 結束碼 0／1／2／3 的定義表、recipe 清單表、檔案擁有權表

需要提到時，放一格 `註記`，文字寫「見 01_purpose.md」這種指路就好，不要展開。

**3. 圖只畫文字講不清楚的。** 只有兩類：

- **模組邊界與資料流**：元件是誰、之間傳什麼、誰呼叫誰。要畫到能對應成模組邊界（之後會由 lint 強制：import-linter、鏡射、黑箱）。
- **主要流程**：時序、分支、每一步誰寫了什麼檔、在哪裡失敗會停在什麼狀態。

**4. 頁數上限 10。** 頁清單你自己決定。說不出「為什麼這頁不是在重畫文件」的頁就不要畫。

**5. 名詞紀律**：只用 `CONTEXT.md` 的詞。不得出現 _Avoid_ 列的舊說法（專案、專案根、專案檔、動詞、子命令、下游、接入、三方合併、`.version`、`.<repo>/`、tracked 檔、版控檔、簽章、信任來源、導入根、`<name>`），也不得出現不存在的 recipe（`verify`、`ensure`、`init`、`diff`、`accept`、`rollback`）。`init.toml` 與「範本」是現行用語，可以用。「初始檔」不要寫成「模板檔」。

## 契約的必要事實（摘自上列檔案；有疑義以原檔為準）

- **兩方**：使用者（被承諾）↔ VK（提出承諾）。使用者兩個情境：導入、出貨（細節見 01，不要上圖展開）。
- **VK recipe**：`just vendor_kit <recipe>`。常用 `add`、`upgrade`、`dev`；進階 `remove`、`undev`、`update`、`sync`、`install`、`uninstall`、`prune`、`help`。另有首次導入用的啟動器 `bootstrap.sh`（下載引擎 + 呼叫 `install`）。`update` 只查，`upgrade` 才套用；`sync`、`prune`、`help` 不改任何進 git 的檔。
- **元件**：引擎（容器內跑、承載全部規則）、薄殼（`.vendor_kit/` 內五檔 `entry.just`、`vendor.just`、`log.sh`、`.gitignore`、`ci/check.sh`，進 git，只啟動與轉發，不解讀 repo 內容的意義）、啟動器（薄殼內的 POSIX sh 片段與 `bootstrap.sh`）、工具 image（純資料）、引擎 image、registry。
- **可寫 recipe 的固定時序五步**：(1) 建執行紀錄（早於任何寫入、拉 image、起引擎）；(2) 建進度檔（早於第一個內容寫入；`--dry-run` 不建）；(3) 多個工具時先對全部工具完整預檢，任一不過就整體不動、以 1 結束並列出每個原因；(4) 寫入；(5) 最後才改版本鎖定行。開始前發現未完成的進度檔就先恢復再繼續；唯讀 recipe 只偵測不恢復。`gen/tools.just` 最後寫、與 `cache/` 在同一個 apply 內原子替換（ADR-0004）。
- **升引擎是兩段式**（ADR-0007 §5）：第一段換上新引擎就停下、以 1 結束、要求重跑；第二段由新引擎接手做事。薄殼重產只由 `install`、`upgrade vendor_kit` 觸發；`sync` 發現薄殼不符只回 1 提示 `upgrade vendor_kit`（ADR-0007 §4）。
- **安裝目錄唯一且禁止巢狀**：安裝目錄 = `.vendor_kit/` 的直接父目錄；一個 repo 可有多個，各自一份版本鎖定行、互不共享；上層或下層已有安裝目錄時 `install` 以 1 拒絕。VK recipe 只准在安裝目錄執行，在別處以 1 拒絕並印出該切到哪裡。
- 其餘（基準版合併、CI 模式五項紅燈、薄殼自描述標頭、介面版、release 資產、離線導入、執行紀錄）請自己讀對應 ADR。

## 輸出格式（一字不差照這個形狀）

最前面先一段頁清單，然後每頁一段。

```
# 頁清單

1. <頁名> | 回答: <一句話說這頁回答什麼問題> | 不是重畫文件的理由: <一句話>
2. ...

## <頁名>

泳道:
- <泳道名>
- <泳道名>
（沒有泳道就寫一行「- 無」）

方塊:
- B1 [方塊型別] <泳道名> | <方塊上的文字，一行，最多 24 字>
- B2 [判斷] <泳道名> | <方塊上的文字>
- ...

連線:
- B1 -> B2 | <標籤，沒有寫「無」>
- B2 -> B5 | 是
- ...

服務不變量: 1, 4, 8
```

規則：

- `# 頁清單` 的頁名與 `## <頁名>` 一字不差對應，頁數 ≤ 10。
- 每頁恰好四個小節：`泳道:`、`方塊:`、`連線:`、`服務不變量:`，順序固定，一頁各一次。
- 方塊編號在每頁內從 `B1` 連號。
- 方塊型別只用：`起點`、`動作`、`判斷`、`資料`、`結束`、`註記`。`資料` 用來表示被寫或被讀的檔／image；流程頁要讓「這一步寫了哪個檔」看得出來。`結束` 的文字寫出結束碼與停在什麼狀態（例如「1：未寫任何檔」）。
- 判斷方塊至少兩條出邊，而且每條都帶標籤（`是`／`否`或具體條件）。
- 沒有泳道的頁，方塊行的泳道欄寫 `-`；有泳道的頁，每個方塊都要屬於列過的某個泳道。
- 連線只能連同一頁列過的方塊。
- `服務不變量:` 只寫 1–11 的編號，逗號分隔，一到四個。不要把不變量畫成方塊。
- 每頁 8–18 個方塊。
- 不要在這些段落之外加說明、前言或結論。
