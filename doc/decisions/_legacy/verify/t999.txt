refactor(test): the catalogue's descriptions live beside their tests, and the document is generated
## The principle this implements

Stated by the repo owner as a repo-wide development rule:

> 人工維護時間長了就會腐爛,應該要能用腳本處理,表格框架可以做一次性維護,
> 後續增加減少表格都是使用腳本做處理

Sharpened into the form a reviewer can apply:

**A person may AUTHOR. A person may never be the MECHANISM that keeps two
things in agreement.**

- A one-time framework -- which catalogues exist, how a section is laid out --
  may be set up by hand.
- Every subsequent addition and removal is done by a script.
- Prose a generator cannot produce is authored, but it is authored **where the
  thing it describes lives**, so nothing has to be kept in step afterwards.

This is invariant 10 ("documentation is derived, never duplicated") applied to
the case invariant 10 does not settle: what to do when part of the content is
genuinely human-written. The answer is not "store it in a document"; it is
"store it at the source and generate the document".

## What is wrong today

`script/test/sync-doc-counts.sh` works like this:

```
_catalog_collect_descriptions   # read the Description cells OUT of doc/test/*.md
<regenerate the rows from @test names>
_catalog_apply_descriptions     # paste them back IN
```

So **`doc/test/unit.md` is itself the source of truth for the descriptions**,
and the human is the sync mechanism. Three consequences, all observed:

1. **A merge can silently destroy them.** Twice in one working session:
   a line-level union dropped a whole catalogue section's body while leaving its
   heading (24 hand-written cells lost, `just test` still green), and a
   section-wise merge reverted six filled cells to `-` placeholders. The gate
   passed over both, because `sync-doc-counts.sh` regenerates counts from the
   tree and a consistent count says nothing about missing content.
2. **A rename orphans the description.** The row's key is the test name; rename
   the test and the description is stranded with nothing to notice.
3. **Two hand-kept rosters exist only to manage the decay**:
   `script/test/catalog-description-baseline.txt` (shrink-only list of rows that
   predate the rule) and `script/test/catalog-description-exemptions.txt`. Both
   are the list-that-rots shape.

Measured: `doc/test/unit.md` carries 1,658 per-test rows, of which **761 (46%)
hold the `-` placeholder**.

## The change

**1. The description's source of truth moves next to the test.**

```bash
# why: an empty scan root is how this lint silently stopped covering
# anything -- it must fail, not pass over nothing.
@test "just provenance: a missing scan root fails rather than passing vacuously (#948)" {
```

The marker format is a decision for the implementation; it must be readable by
the generator and by a person, and it must sit where the author is already
typing. Follow the conventions the repo already has for line-attached markers
(`tool-pin:`, `allow-begin`).

**2. `sync-doc-counts.sh` becomes one-directional.** It READS descriptions from
the spec files and WRITES the catalogue. It never reads the catalogue for
content. After this, `doc/test/*.md` is 100% generated and is never hand-edited.

**3. The catalogue stays committed.** A reader browsing the repo should see it.
Merge conflicts in it become purely mechanical -- regenerate and move on -- and,
critically, **can no longer lose anything**, because the source is the spec file.

**4. The two roster files are deleted.** With the description beside the test, a
spec without one is a finding; there is no back-catalogue to grandfather and no
exemption list to maintain.

**5. The existing content is migrated mechanically.** The ~897 filled
descriptions are keyed by test name, so a script can move each to its `@test`.
The 761 placeholders are the work that remains, and it is real work -- but it is
work that produces something, unlike a placeholder.

## Relationship to the other issues

- **#978** shrinks. Its removal of the five grand-total lines stands -- those are
  what every branch edits, and they caused 61 conflicts in 65 merges. Its removal
  of the per-test TABLE does not: the table is kept and generated instead.
  ADR-00000028 needs an Amendment recording that.
- **#976 / #922** is redirected rather than closed. Its lint keeps its rule --
  a description must say WHY the case matters and must not restate the test name
  -- but it checks the spec file instead of the catalogue, and it loses the
  baseline and exemption files.

## Acceptance

- `doc/test/*.md` is regenerated from scratch by the script and is byte-identical
  to what is committed; no path in the tooling reads content out of it.
- Deleting a description from a spec file makes the gate red; deleting one from
  the catalogue is invisible because the next regeneration restores it.
- Renaming a test carries its description with it, proven by a test.
- `catalog-description-baseline.txt` and `catalog-description-exemptions.txt` are
  gone.
- No hand-written description is lost in the migration: proven by comparing the
  set of (test name -> description) pairs before and after, not by inspection.
