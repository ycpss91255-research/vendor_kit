ci.sh: kcov/kcov compose runner can't reach deb.debian.org from networks where the TW mirror is reachable
## Symptom

Local `make -f Makefile.ci test` fails on networks where `deb.debian.org` is unreachable (ISP routing issue, regional outage, etc.) even when the Taiwan mirror configured in `setup.sh`-generated `.env` (`APT_MIRROR_DEBIAN=mirror.twds.com.tw`) responds normally:

```
$ make -f Makefile.ci test
W: Failed to fetch http://deb.debian.org/debian/dists/bookworm/InRelease
   Could not connect to deb.debian.org:80 ... connection timed out
E: Unable to locate package bats
[ci] ERROR: apt-get install failed for bats/shellcheck deps.
```

While `curl -I http://mirror.twds.com.tw/debian/dists/bookworm/InRelease` from the host returns `HTTP/1.1 200 OK` immediately. Containers spawned by docker compose inherit the host network, so this is purely a sources.list issue.

## Root cause

`template/compose.yaml` declares the `ci` service on `kcov/kcov` without any apt-mirror plumbing. `script/ci/ci.sh::_install_deps` then runs `apt-get update` against that image's default `/etc/apt/sources.list` (which points at `deb.debian.org`). The `APT_MIRROR_*` env keys that `setup.sh` writes to `.env` are not propagated into the `ci` service.

## Fix options

**(a) Plumb the mirror env through compose + ci.sh** (smaller scope):
- Add `APT_MIRROR_DEBIAN=${APT_MIRROR_DEBIAN:-deb.debian.org}` to `compose.yaml` `ci.environment`
- In `_install_deps`, before `apt-get update`, rewrite `/etc/apt/sources.list` to use `$APT_MIRROR_DEBIAN`

**(b) Bake bats + bats-mock + shellcheck into the test-tools image** (bigger but eliminates the per-run apt-install entirely):
- Add `bash` + `bats` + `bats-mock` to `dockerfile/Dockerfile.test-tools` (currently alpine, would need bash for bats to run)
- Switch `compose.yaml` `ci` service to `ghcr.io/ycpss91255-docker/test-tools:<version>`
- `ci.sh::_install_deps` becomes a no-op when bats already exists

(b) is the cleaner long-term direction (ci.sh apt-install is a per-run cost that compound across CI matrix shards); (a) is the minimum unblock.

## Context

Discovered while validating PR #162 locally — the kcov/kcov runner couldn't reach `deb.debian.org` from the dev host but `mirror.twds.com.tw` worked fine; had to manually rewrite sources.list inside an ad-hoc `docker run` to verify the change. Workflow now blocks anyone hitting the same routing issue.
