bug: _lib.sh _detect_lang returns "zh" for zh_TW locale (inconsistent with build.sh/run.sh/i18n.sh)
## Summary

`_lib.sh`'s fallback `_detect_lang()` returns `"zh"` for `LANG=zh_TW.*`, while every other detection site returns `"zh-TW"`. Latent bug: when `i18n.sh` is available (normal case) `_lib.sh`'s fallback isn't used, so the bug hides. Triggers when `i18n.sh` is missing — zh-TW users fall through to English messages because `_LANG=zh` matches none of the `zh-TW:` case patterns, lands on the `*:` fallback.

## Root cause (v0.9.10)

| file:line | returns for zh_TW |
|-----------|-------------------|
| `script/docker/_lib.sh:22` | `"zh"` ← **inconsistent** |
| `script/docker/build.sh:17` | `"zh-TW"` |
| `script/docker/run.sh:15` | `"zh-TW"` |
| `script/docker/i18n.sh:18` | `"zh-TW"` |

Almost certainly a copy-paste typo in `_lib.sh`.

## Fix

```diff
 _detect_lang() {
   case "${LANG:-}" in
-    zh_TW*) echo "zh" ;;
+    zh_TW*) echo "zh-TW" ;;
     zh_CN*|zh_SG*) echo "zh-CN" ;;
     ja*) echo "ja" ;;
     *) echo "en" ;;
   esac
 }
```

One-line patch.
