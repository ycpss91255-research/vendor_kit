exec.sh: support -- separator before CMD (consistent with run.sh)
## Problem

`./exec.sh` does not support `--` as a flag/CMD separator. `./run.sh` does. This breaks symmetry between two scripts that share `-t/--target` + CMD-passthrough semantics, and forces users into awkward workarounds when the inner command starts with a flag-shaped token (e.g. `-h`, `--version`).

## Current behaviour

`./run.sh` parse loop (`script/docker/run.sh`):

```bash
--)
  shift
  CMD_ARGS+=("$@")
  break
  ;;
*)
  CMD_ARGS+=("$1")
  shift
  ;;
```

You can write `./run.sh -t devel -- bash -c 'echo -h is fine'` and the `--` cleanly delimits run.sh flags from container CMD.

`./exec.sh` parse loop (`script/docker/exec.sh`):

```bash
*)
  break
  ;;
```

There is no `--` arm. The user can run `./exec.sh -t devel ls /tmp` (positional works), but `./exec.sh -t devel -- bash -c '...'` treats `--` as the start of CMD and the `--` literal is sent to `docker exec`, which rejects it (or silently does the wrong thing depending on shell version).

More importantly, `./exec.sh -t devel my-tool --version` works only by accident -- `--version` is the second positional, falls under `*) break`, and the rest of `"$@"` is the CMD. Fine. But `./exec.sh --version` (intending to pass `--version` to the inner CMD, no other args) fails because `--version` is consumed as an exec.sh unknown flag and hits `*) break` with an empty CMD list.

## Why it matters

The mental model is: `run.sh` and `exec.sh` are siblings -- both take `-t TARGET` and a trailing CMD. Users learn one then use the other. The missing `--` is a tripping point especially for CI scripts where the inner command is dynamic and might start with a dash.

## Proposed fix

Add a `--` arm to exec.sh's parse loop, mirroring run.sh:

```bash
--)
  shift
  break  # remaining "$@" is CMD passthrough
  ;;
*)
  break
  ;;
```

(exec.sh already uses `break` on first positional and passes `"$@"` to `docker exec`, so the `--` arm just consumes the `--` itself and lets the rest flow through unchanged.)

## Acceptance

- `./exec.sh -t devel -- bash -c 'echo ok'` runs `bash -c 'echo ok'` inside the devel container; the literal `--` is NOT passed to `docker exec`.
- `./exec.sh -- my-tool --version` (no `-t`, default target) runs `my-tool --version` inside the default container.
- `./exec.sh -t devel ls /tmp` (current positional path) still works -- backward compatible.
- bats coverage for: with-`--`, without-`--`, `--` plus flag-shaped first CMD arg.
- ShellCheck clean.
- `-h` lists `--` in the usage synopsis for symmetry with `run.sh`.
