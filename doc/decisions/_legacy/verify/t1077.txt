fix(upgrade): upgrade.sh has no compatibility forwarder, so the command that just worked exits 127
`init.sh` got a compatibility forwarder at the old path. `upgrade.sh` did not,
and it is the one a human types.

## Reproduce

    git clone --recurse-submodules https://github.com/ycpss91255-docker/omniverse_web_viewer
    cd omniverse_web_viewer          # .base/.version = v0.41.0
    ./.base/upgrade.sh v0.43.0-rc2   # succeeds, exit 0
    ./.base/upgrade.sh v0.43.0-rc2   # 127: No such file or directory

After the upgrade:

    .base/init.sh                        EXISTS  (compatibility forwarder)
    .base/upgrade.sh                     MISSING
    .base/dist/script/base/upgrade.sh    the implementation

Same on `v0.43.0-rc1`, so this is not new in rc2.

## Why this is the forwarder's own argument

`.base/init.sh` opens with:

> THIS IS NOT THE IMPLEMENTATION. ... this file exists only so that callers
> which have ALREADY SHIPPED can still find it.
> Two callers name exactly that path and neither can be fixed retroactively

That reasoning applies to `upgrade.sh` at least as strongly, and arguably more:
`init.sh` is named by scripts, `upgrade.sh` is named by people, runbooks and
downstream docs. Every consumer released up to `v0.42.0` documents
`./.base/upgrade.sh vX.Y.Z` as the flat-layout command -- including
`ycpss91255-docker/isaac`'s and `omniverse_web_viewer`'s own harness notes.

The failure mode is also worse than a wrong path: exit 127 with no message.
The upgrade that just succeeded removed the command the user ran, and the
closing "Next steps" says nothing about it.

## Severity: moderate, not blocking

`just base upgrade` works and is the documented preferred form:

    $ just base upgrade --check
    Local:  v0.43.0-rc2
    Latest: v0.42.0
    exit 0

So there is a working path. What breaks is anything that hardcoded the old
one -- CI steps, runbooks, a second upgrade in the same session -- and it
breaks with no explanation.

## Suggested fix

The same forwarder `init.sh` already has, pointing at
`dist/script/base/upgrade.sh`. If the intent is to retire the old entry point
rather than support it, a forwarder that prints a one-line deprecation notice
and then execs would still be better than 127 -- the user learns where the
command went instead of guessing.

Refs #1054, which frames this class exactly ("a change moved something, and
nothing was in a position to notice"). Its three listed items are the
`init.sh` path, the smoke tree, and `_init_protected_paths`; this is the
fourth and it is the sibling of the first.

## Environment

`v0.43.0-rc2` and `v0.43.0-rc1`, consumer `omniverse_web_viewer@4375148`
(`.base` at v0.41.0), throwaway clone, Ubuntu 24.04.
