fix: just --list shows broken module descriptions (docker empty, base truncated)
## Problem

`just --list` (in a downstream repo and in base) renders broken module
descriptions because `just` uses only the comment line(s) immediately
adjacent to each `mod?` line (last line of a contiguous block; nothing if a
blank line separates it):

```
Available recipes:
    default      # Default: list available recipes (replaces `make help`).
    base ...     # the script relocation land in        <- truncated mid-sentence fragment
    docker ...                                            <- no description at all
    template ... # script/local/ and registers it. ...   <- last-line fragment (reads OK by luck)
```

- `docker ...` -- NO description (a blank line separates `mod? docker` from the file-header comment).
- `base ...` -- truncated mid-sentence fragment ("the script relocation land in"); the comment above is a multi-line paragraph and just takes only its last line.

Source: `dist/script/justfile` mod? comment placement. The base root
`justfile` (`mod? docker/test/release`) has the same defect. Shipped to every
consumer via the subtree.

## Fix

Put a single clean one-line doc comment directly above each `mod?` line (no
blank line between, no multi-line paragraph). Keep any longer rationale as a
separate header block ABOVE, separated by a blank line so just does not grab
it. Example:

```just
# Container-ops: build / run / exec / stop / prune / setup / setup-tui
mod? docker 'script/docker/justfile.docker'

# Manage the .base subtree: init / upgrade / update / completions
mod? base 'script/base/justfile.base'

# Repo-local command groups: `just template new <name>` scaffolds + registers
mod? template 'script/template/justfile.template'
```

## Acceptance criteria

- [ ] Each top-level `mod?` (docker/base/template in `dist/script/justfile`; docker/test/release in base root `justfile`) has a clean one-line adjacent doc comment
- [ ] `just --list` shows a sensible one-line description for every module, no empty or mid-sentence-fragment entries
- [ ] Regression test (justfile_spec.bats): assert each top-level `mod?` line has a non-empty adjacent (no blank-line-gap) comment whose text is not an obvious sentence fragment
