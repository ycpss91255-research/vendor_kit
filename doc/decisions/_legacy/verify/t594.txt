feat(justfile): support repo-local recipes via import? + seed justfile.local scaffold
## Problem

The downstream `justfile` is a fixed symlink to `.base/script/docker/justfile` with a hard-coded recipe set (`build` / `run` / `exec` / `stop` / `prune` / `setup` / `setup-tui` / `upgrade`). There is **no extension point** for repo-specific recipes. A downstream repo that wants its own `just` recipe (e.g. isaac's multi-instance orchestration `just instance-up <name>`) currently has no clean path:

- Editing the symlink target = editing base (a subtree pull overwrites it).
- Committing a real `justfile` that `import`s base = `init.sh`'s `_create_symlinks` clobbers it back to the symlink on every init / upgrade resync.

So today repo-specific commands fall back to `./script/*.sh` invoked directly -- not in `just --list`, inconsistent with the `just`-first workflow.

## Proposal (two parts, both needed)

1. **Add `import? 'justfile.local'` to the base justfile** (optional import -- `just` supports it natively; a missing file is not an error). This lets a downstream repo add repo-local recipes in `justfile.local` that survive subtree pulls and show up in `just --list`.

2. **Seed a `justfile.local` scaffold in `init.sh`** -- created only when absent (non-clobbering), content is a comment template plus one example recipe. The point is that **the file always exists, so users never have to guess whether the mechanism is available**: open it and the how-to is right there.

## Why

Every base repo eventually needs a repo-specific recipe; right now the only option is `./script/*.sh` (off the `just --list` discovery path, inconsistent). Concrete driver: `ycpss91255-docker/isaac`'s per-instance create/launch orchestration. This is an org-wide gap, not isaac-specific.

## Notes

- `import?` precedence: the main justfile (base) recipes take precedence; `justfile.local` is for **adding** recipes (not overriding `build` / `run` / ...). If override is ever needed it can be a follow-up.
- `justfile.local` is committed by the downstream repo (persistent + shared); `init.sh` only seeds the scaffold when the file is missing.
- Mirrors the existing convention: `init.sh` seeds a `.gitkeep` for `config/` when absent rather than laying down the full tree.

## Verified against current source

No `import` directive in the justfile at v0.40.0, v0.41.0, or `main`; `init.sh` `_create_symlinks` creates the `justfile` symlink and does not seed a `justfile.local`. No existing issue/PR covers this.

Folded into the justfile-layering epic #625. Superseded by #633
(`template` namespace + `just template new <name>`): the original
`import? 'justfile.local'` plan is unworkable because `just` treats a
duplicate recipe name across an import as a hard error (not a shadow), so
repo-local recipes must be namespaced via `mod?` rather than imported
top-level. #633 closes this. Design: ADR-00000010.
