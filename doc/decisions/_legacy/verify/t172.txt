feat(init/upgrade): sync .gitignore on both new-repo init and template upgrade so derived artifacts stay untracked
## Summary

`init.sh` writes a fixed 6-line `.gitignore` (`.env / .env.bak / compose.yaml / setup.conf.bak / coverage/ / .Dockerfile.generated`) on the **new-repo path**, but **none of the existing-repo upgrade flows touch `.gitignore`**:

- `init.sh` existing-repo branch (Dockerfile already present) — does not check, does not patch
- `upgrade.sh` / `make -f Makefile.ci upgrade` — does not check, does not patch
- `git subtree pull` — only touches the `template/` subdirectory

As a result, when the template adds a new derived artifact (e.g. v0.9.0 made `compose.yaml` a derived artifact and gitignored it; later `.env.bak` / `setup.conf.bak` / `coverage/` / `.Dockerfile.generated` were added), **downstream repos have no automatic catch-up mechanism**. Users must hand-edit `.gitignore` per repo, or live with derived artifacts polluting their working tree.

## Audit on 17 downstream repos (against template v0.12.3)

| Group | `.gitignore` content | `git ls-files compose.yaml` |
|---|---|---|
| `env/ros_noetic` | full 6 lines + `.claude/` | not tracked |
| `app/ros1_bridge` | custom (4 lines + `bridge.yaml` + `.claude/`) | not tracked |
| `agent/*` × 4 | `.env / .env.gpg / data/ / .claude/` | **tracked** |
| `env/*` × 5 (excl. ros_noetic) + `app/*` × 5 | only `.env / .claude/` | **tracked** |

15/17 repos still git-track `compose.yaml`. Every `setup.sh` regen of compose.yaml (the default behaviour of `build.sh` / `run.sh`) shows up as a modification in `git status`, polluting the working tree on every build/run. Other derived artifacts (`.env.bak` / `setup.conf.bak` / `coverage/` / `.Dockerfile.generated`) are not currently mis-committed only because they are generated less often, but the missing `.gitignore` entries are the same root cause.

## Proposal

Treat `.gitignore` as a **template-managed canonical set**, and run sync in both `init.sh` (new-repo + existing-repo paths) and `upgrade.sh` / `make upgrade`. Sync fills in missing entries while preserving user-defined lines.

### Canonical entries (sourced from template; evolves with template)

```
.env
.env.bak
compose.yaml
setup.conf.bak
coverage/
.Dockerfile.generated
```

Future derived artifacts get added to this list, and downstream repos pick them up automatically on the next upgrade.

### Sync strategy

- **Append missing entries**: any canonical entry not present in `.gitignore` is appended at the end, preceded by a marker block comment such as `# managed by template (do not remove)` so the boundary is recognisable.
- **Preserve user-defined lines**: repo-specific entries (`bridge.yaml` / `data/` / `.env.gpg` / `.claude/` etc.) are left untouched.
- **Do not remove old entries**: even if the template later removes an entry from the canonical set, do not actively delete it downstream (avoid surprise); call it out in CHANGELOG instead.
- **Idempotent**: re-running sync does not duplicate appends.

Implementation-wise, extract the canonical list into a shared lib (e.g. `template/script/docker/lib/gitignore.sh`), consumed by `init.sh` (both new and existing branches) and `upgrade.sh`.

### Integration points

- `init.sh` new-repo path: write the full file (current behaviour), but source the canonical list from the shared lib.
- `init.sh` existing-repo path: run sync.
- `upgrade.sh` / `make -f Makefile.ci upgrade`: run sync (can sit alongside the existing init.sh symlink resync block).
- `make -f Makefile.ci upgrade-check`: detect `.gitignore` drift and report, without mutating files.

### Follow-up beyond this issue

After the template PR merges and a tag is cut, the 15 outdated downstream repos need a batch sweep:

1. Run `/batch-template-upgrade` to bump them to the version that contains the sync — `.gitignore` is filled in automatically.
2. For the 15 repos still tracking `compose.yaml`, additionally `git rm --cached compose.yaml`, commit, PR.

That sweep is handled via `/batch-pr` or `/batch-template-upgrade` and is out of scope here.
