fix(toml-bridge): --merge always exits 1 and conf.sh swallows it
## Context

On branch `feat/toml-config-unification` (epic #1127), the merge commit
`1567b8d2` ("Merge branch 'main' into feat/toml-config-unification")
resolved the conflict in `dockerfile/toml_bridge.py` by a line-level
union instead of picking a side.

Function inventory of the two parents:

| revision | lines | contents |
|---|---|---|
| `5cc9fb9b` (main side) | 107 | naive `_emit_kv`, `_merge_toml`, `main` |
| `ff53be6a` (feature side) | 108 | `_ARRAY_SPEC`, `_format_value`, `_emit_array`, array-aware `_emit_kv`, `_merge_layers`, `main` |
| `1567b8d2` (merge) | 176 | BOTH merge functions, a duplicated `main()` body, and the feature side's `_emit_kv` body displaced |

The feature side is exactly the shape #1130 (D4: type-aware merge
semantics for TOML layers) landed. After the union the file is the
concatenation of both sides: the D4 type handling is still physically
present but no longer reachable from any live call path. The branch tip
`195b5976` is still 176 lines, so the defect is live, not historical.

This class of failure -- a line-level union merge producing a file that
is the concatenation of both sides -- is the same shape as
previously-recorded incidents in this repo; see #1103 (a merge producing
a duplicate CHANGELOG category heading). What is different here is that
nobody noticed: see the downstream impact under Defect 1.

## Problem

### Defect 1: `--merge` mode always exits 1

In the merged file, `_merge_toml()` (line 69) lost its `return merged`.
Lines 99-106 are the displaced body of the feature side's `_emit_kv()`;
they reference `entries` and `section`, neither of which exists in
`_merge_toml`'s scope.

Reproduced (with a stubbed `tomllib`, since the function fails before any
TOML parsing matters):

```
$ toml-bridge --merge --kv a.toml b.toml
toml-bridge: name 'entries' is not defined
rc=1
```

`main()` (line 135) also carries a duplicated body:

- lines 136-154 parse args and call `_merge_toml(args)`
- lines 155-172 re-parse and call `_merge_layers(argv)`

Because the first block's `except Exception` catches the `NameError` and
does `raise SystemExit(1)`, the second block -- the one that calls the
CORRECT `_merge_layers` -- is never reached in merge mode.

### Defect 2: `_emit_kv` cannot express arrays of tables

`_emit_kv()` (lines 51-66) is what `main()` actually calls. It does not
use `_format_value()` (line 34), `_emit_array()` (line 41), or
`_ARRAY_SPEC` (line 21) -- those three are reachable only from the dead
fragment inside `_merge_toml`.

Measured output vs what the shell layer expects:

```
actual:   build  init   True
          image  rules  [{'rule': 'prefix:docker_'}, {'rule': '@basename'}]
expected: build  init   true
          image  rule_1 prefix:docker_
          image  rule_2 @basename
```

The shell side reads the numbered-key shape:

- `_conf_list_sorted` matches `<prefix><digits>` (`conf.sh:530-537`)
- `detect_image_name` wants `rule_` (`setup_detect.sh:230`)
- `_resolve_deploy_context` wants `device_` / `env_` / `tmpfs_` /
  `port_` / `cap_add_` (`deploy.sh:342-369`)

### Why this is silent rather than loud

`_conf_load_layers()` in `dist/script/docker/lib/conf.sh:432-449` takes
the TOML branch whenever every existing layer ends in `.toml` (the normal
case), calls `toml_bridge_merge --kv` at line 447, and then does
`return 0` at line 448 WITHOUT checking the exit status.

So the config handle comes back empty and every `_conf_get_into` silently
falls through to its default value. The missing exit-status check is
precisely what turns a hard failure into a wrong-value-with-rc-0.

## Proposal

1. Resolve the botched merge in `dockerfile/toml_bridge.py`: keep ONE
   merge function and ONE `main()` body. `_merge_layers()` (lines
   109-132) is complete and correct; `_merge_toml()` is the damaged one.
2. Make `_emit_kv()` use `_format_value()` for scalars and
   `_emit_array()` for lists, so booleans render lowercase and
   arrays-of-tables render as numbered keys.
3. Make `_conf_load_layers()` (`conf.sh:447-448`) check the bridge exit
   status instead of unconditionally returning 0 -- a failing bridge must
   be loud, not an empty handle.
4. Add the regression test that would have caught this.

## Acceptance criteria

- [ ] `toml_bridge.py` has exactly one merge function and one `main()`
      body; `_ARRAY_SPEC` / `_format_value` / `_emit_array` all sit on a
      live call path.
- [ ] `toml-bridge --merge --kv a.toml b.toml` over two layers exits 0
      and emits the numbered-key shape (`image\trule_1\tprefix:docker_`).
- [ ] Booleans render lowercase (`build\tinit\ttrue`).
- [ ] When the bridge exits non-zero, `_conf_load_layers()` fails loudly
      instead of returning an empty handle with rc 0.
- [ ] A spec asserts that `--merge --kv` over two layers produces the
      numbered-key shape, and another asserts that a non-zero bridge exit
      propagates.
