refactor(test): four families that restate what a sibling already proves, and one that proves nothing
## Context: the ratio table this comes from

The audit measured every test family as tests divided by distinguishable
properties (a property = one production decision a test can tell apart), using
timings from CI run `34013117272` (main, all green, 2026-09-06; 3980 tests
timestamped, median 490 ms per test).

| family | files | tests | properties | tests per property |
|---|---|---|---|---|
| wrapper i18n | 6 | 50 | 18 | **2.78** |
| `run.sh` xhost branch | 4 | 13 | 4 | **3.25** |
| wrapper CLI surface | 8 | 124 | 41 | 3.02 |
| CI-workflow YAML specs | 9 | 309 | ~214 | 1.44 |
| TUI | 5 | 298 | ~247 | 1.21 |
| upgrade/init | 5 | 240 | ~206 | 1.17 |
| compose/env emission | 7 | 177 | ~155 | 1.14 |
| lint-driver | 28 | 707 | ~556 | 1.27 |

**The table is mostly healthy.** Every family except the first two sits between
1.1 and 1.5. So this issue is about **signal, not wall clock** -- the time saved
by all four items below is under a second of critical path, and the cost argument
should not be used to justify any of them.

Four items, all measured by mutation.

## 1. wrapper i18n: 20 tests share one assertion token that cannot tell the locales apart (#19)

**Defect.** The zh-TW and zh-CN usage heredocs both **begin with the same two
characters** meaning "Usage" (`dist/script/docker/wrapper/stop.sh:34` and `:54`;
same in `build.sh:73/:124`, `run.sh:107/:150`, `exec.sh:62/:101`,
`prune.sh:72/:138`). Every zh-CN test asserts exactly that token, byte-identical
to its zh-TW sibling.

**Evidence.**

- Mutation, verified: in a temporary worktree, change `stop.sh`'s arm to
  `zh-TW|zh-CN)` and rename the real zh-CN arm to `__dead_arm)`, so `--lang zh-CN`
  renders the **Traditional** heredoc and the entire Simplified block is
  unreachable. `./script/test/test.sh --bats-path test/bats/unit/stop_sh_spec.bats`
  returns 31/31 green, including
  `ok 3 stop.sh --lang zh-CN prints Simplified Chinese usage text` and
  `ok 13 stop.sh in /lint/ layout maps zh_CN.UTF-8 to zh-CN`.
- The ten: `build_sh_spec.bats:441, 483`; `run_sh_spec.bats:628, 670`;
  `exec_sh_spec.bats:132, 331`; `stop_sh_spec.bats:92, 181`;
  `prune_sh_spec.bats:120`; `dist/test/bats/smoke/devel-test/script_help.bats:154`.
- No compensating gate: `script/test/drivers/i18n_orphan.sh:33` restricts its
  haystack to "README.md ALONE, never the code tree"; `readme_sync.sh` is a
  per-section fingerprint. Grepping the 26 drivers for `zh-CN|zh_CN` finds three
  comment lines.
- The sibling to copy is next door: `build_sh_spec.bats:660` asserts a
  Simplified-only string, and `exec_sh_spec.bats:166` does the same.

**Correction to keep.** The claim "the whole Simplified block could be deleted and
every gate stays green" is **false** -- deleting the zh-CN arm makes output fall
through to the English `*)` branch, the token is absent, and the assertion fails.
These tests do pin (a) that zh-CN is an accepted `--lang` value and a
`_detect_lang` output, and (b) that some arm answers in Chinese. The only property
they cannot distinguish is **Traditional versus Simplified** -- and the defect is
symmetric, so it is 20 tests sharing one token, not 10.

**Fix.** Give each zh-CN assertion a Simplified-only token and each zh-TW
assertion a Traditional-only token, following the discipline
`build_sh_spec.bats:660` already uses. Then collapse the family: `_detect_lang`
(`i18n.sh:21`) and `_wrapper_lang_prepass` (`wrapper.sh:131`) are each one shared
function and each need testing once -- per ADR-00000015 (test files mirror source
files), `_detect_lang` belongs in a spec named for `lib/i18n.sh`, and
`wrapper_lib_spec.bats` is already `_wrapper_lang_prepass`'s home. Keep one wiring
test per wrapper instead of one per (wrapper x locale). 50 tests down to about 24,
with strictly more signal.

**Leave `dist/test/bats/smoke/devel-test/script_help.bats:154` alone** -- its
header (`:145-146`) states its job is #222's argument-order independence
(`--help --lang X` versus `--lang X --help`), and it does that correctly.

## 2. `bats-fragile` re-runs 353 tests the coverage matrix already ran, and the comment claims it does not (#27)

**Defect.** `self-test.yaml:633-635` states the design intent: "this job runs
exactly those fragile specs, so the difference is preserved and there is **zero
double execution**: every unit test runs somewhere (non-fragile in coverage/kcov,
fragile here)." The claim is at **test** granularity; the mechanism selects whole
**files**: `script/test/drivers/bats.sh:404` is
`grep -rlE "${_FRAGILE_GUARD_RE}" .../test/bats/unit` (`-l`, one filename stands
for the whole file), and `bats.sh:278`'s
`_COVERAGE_FULL_SUITE_POOLS=(test/bats/unit test/bats/integration)` puts those same
files in the coverage pool with no exclusion.

**Evidence.**

- Running the driver's own selectors: `_coverage_pool_files` returns 176 files,
  `_fragile_unit_files` returns 9, the intersection is 9, and fragile-not-in-pool
  is 0.
- Counting the tree: those 9 files hold 376 `@test`s, of which 23 carry
  `[ "${COVERAGE:-0}" = 1 ] && skip`. All 23 guards are inside individual `@test`
  bodies (none in `setup_file`), so **353 run under kcov as well**.
- Both jobs share an `if:` (`:645` and `:816` are both
  `needs.classify.outputs.code_changed == 'true'`), so those 353 run twice on
  every code PR.
- Critical-path cost is **zero**: in run `34013117272`, `bats-fragile` was 54 s
  wall clock (05:05:59-05:06:53, 41 s in bats) while the slowest coverage shard
  was 534 s (05:05:59-05:14:53) -- eight minutes later.
- The comment is inaccurate in a second place: "This job runs exactly those
  fragile specs" -- "those" is bound by the previous sentence to the tests it
  SKIPS, so both halves make test-granularity claims.
- Its own baseline number is stale too: `:628` says "~1991 unit specs" while
  `test/bats/unit` holds 4383 `@test`s today, making the overlap 353/4383 = 8%.

**Why it matters.** The real cost is about 41 s of duplicated computation and one
concurrency slot, not PR latency. What matters is the comment: the next person
sizing the suite reads "ZERO double-run" and stops reading. #677 removed the old
4-shard bats-unit matrix precisely because it re-ran the whole unit suite; this is
residue from that change.

**Fix -- change the comment, not the mechanism.** The proposal to derive the
guarded test names and select them with `bats -f` was rejected for three reasons:
(1) its premise is wrong -- the guard is not at the top of the body in 6 of the 9
files (`build_sh_spec.bats:880` vs `:890`, `run_sh_spec.bats:1007` vs `:1014`,
`exec_sh_spec.bats:446` vs `:453`, `stop_sh_spec.bats:287` vs `:294`,
`lib_spec.bats:147` vs `:151`, `conf_accessor_spec.bats:292` vs `:296`), so it
would need to parse bats syntax backwards and escape regex metacharacters inside
test names such as `(#797)`; (2) a tag scheme replaces #677's runtime-derived,
bidirectionally-asserted set (`ci_spec.bats:2792`, `:2809`) with a marker that has
to be kept in step with the guard -- the two-sources-of-truth shape this repo keeps
filing bugs about; (3) this second, uninstrumented execution is CI's only remaining
plain-mode unit signal, and this repo has diagnosed kcov perturbation four times
(`doc/changelog/v0.42.md:25` names #613, #869, #895, #898).

The text is mirrored in four places, all of which must change:
`self-test.yaml:633-635`, `script/test/drivers/bats.sh:416`,
`test/bats/unit/self_test_yaml_spec.bats:225`, `doc/test/unit.md:4961`. Fix the
stale "~1991" baseline at `:628` at the same time, or state it as a derived figure.

## 3. bats-mock: an image layer, a version pin and two guards keeping a dependency no spec uses (#31)

**Defect.** `test/bats/unit/test_helper.bash:9` does
`load "${BATS_LIB_PATH}/bats-mock/stub"`, executed by the setup of 147 unit spec
files. **No spec calls it**:
`grep -rnE '^[[:space:]]*(run[[:space:]]+)?(stub|unstub)[[:space:]]' test/ dist/`
returns nothing, and widening the search to the other eight org checkouts in the
workspace also returns nothing.

**Evidence.**

- What keeps it alive: `dockerfile/Dockerfile.test-tools:138-146` (the `tool-pin:`
  marker, `ARG BATS_MOCK_VERSION=v1.2.5`, a `git clone --depth 1`);
  `test/bats/unit/template_spec.bats:773-776`, a pure grep guard whose only
  function is to refuse deletion of this unused dependency (`git log -L` shows it
  landed in the same commit `5c89bf57` as the install and has done nothing since);
  `script/ci/test-tools-pins.sh:107`, the roster probe, so
  `integration/test_tools_pins_spec.bats` asserts its version every run;
  `tool-version-watch.yaml:268-280`, which re-proposes an upgrade for every
  `tool-pin` marker weekly until someone writes `skip=`.
- Downstream cannot use it either: `dfs/*.Dockerfile` and
  `dockerfile/Dockerfile.smoke:164` set `BATS_LIB_PATH=/usr/lib/bats` but install
  only bats-support and bats-assert. bats-mock exists only in
  `Dockerfile.test-tools`.
- A second dead branch in the same file: `test_helper.bash:11-18` sources
  `${BATS_TEST_DIRNAME}/bash_test_helper/src/test_helper.bash`.
  `ls test/bats/unit/bash_test_helper` reports no such file or directory and a
  tree-wide `find` agrees, so that `[[ -f ]]` guard has been a no-op since
  `d009bf6b`.

**All three costs are near zero, and the cost argument should not be used.** The
clone shares a RUN with bats-support / bats-assert
(`Dockerfile.test-tools:141-146`), so removing it drops no layer and about 40 KB of
259-270 MB. Sourcing roughly 100 lines of bash per test measures at about 0.15 ms
(500 iterations: 432 ms versus a 358 ms baseline), under a second across 4322
tests, about 0.1% of the critical path. The only real toil is a
human-reviewed bump PR whenever jasonkarns/bats-mock releases, and it is the least
active of the nine pins.

**Fix.** Remove it in one change: the install
(`Dockerfile.test-tools:138-146`), the `load` (`test_helper.bash:9`), the pin
roster row and the ARG (`test-tools-pins.sh` **refuses** to emit a roster when a
declared pin has no probe, so both must move in the same commit), and the guard
(`template_spec.bats:773-776`). The 14 specs that genuinely need stubbing use the
repo's own `mock_cmd` / `create_mock_dir` (`test_helper.bash:26-40`).

Delete `test_helper.bash:11-18` with it, or actually vendor the subtree it names.
**That half is the more valuable one**, because it announces a helper library to
the reader and the reader goes looking.

**Removal touches more than four places:** `README.md:199` and
`doc/readme/README.{zh-TW,zh-CN,ja}.md` list bats-mock as image content,
`doc/test/unit.md:6241` catalogues the guard test, and
`.claude/hooks/remind_tdd_categories.sh:103` actively tells agents that unit tests
are written "with bats-mock". That last one is also the fairest counter-reading:
this is a **deliberately provisioned** capability (installed, documented,
recommended to test authors) that nobody has taken up, not code someone forgot to
delete. If it is being kept on purpose, say so in the Dockerfile and delete the
guard -- guarding an unused dependency only protects its unusedness.

## 4. `run.sh` xhost: 13 tests over 4 properties, one of them empty and three anti-correlated (#32)

**Defect.** The property "`run.sh` selects the xhost host-ACL by
`XDG_SESSION_TYPE`" has 4 observable outcomes and is written 13 times across 4
files. `run_sh_spec.bats:651`, titled
`run.sh uses xhost +SI:localuser under Wayland session`, has a body consisting
entirely of
`run env XDG_SESSION_TYPE=wayland bash "${SANDBOX}/run.sh" --dry-run` plus
`assert_success`. It asserts nothing about xhost.

**Evidence -- three mutations, all run in a temporary worktree.**

- **Invert the branch** (wayland emits `+local:`, x11 emits
  `+SI:localuser:${USER_NAME}` -- the property in the test's own name completely
  broken): `run_sh_spec:651` ok, `template_spec:3385/:3391/:3397` all ok. Only the
  three behavioural tests in `smoke_helper_spec` go red. Those four tests are blind
  to a total inversion of what they are named for.
- **Delete the whole xhost block** (`grep -c xhost run.sh` = 0):
  `run_sh_spec:651` still reports
  `ok 1 run.sh uses xhost +SI:localuser under Wayland session`. It passes against a
  `run.sh` containing no `xhost` at all -- "empty" is not hyperbole.
- **Behaviour-preserving refactor** (hoist the ACL into `_acl`, then
  `xhost "${_acl}"`): the behavioural tests stay green and
  `template_spec:3391` and `:3397` go **red**. Those three greps are not merely
  redundant, they are **anti-correlated** with the property.
- Relationship between the three spellings: `smoke_helper_spec.bats:216-243`
  (4 tests, exact `assert_output` comparison against
  `/source/dist/script/docker/wrapper/run.sh`) is strictly stronger than the
  shipped `dist/test/bats/smoke/devel-test/display_env.bats:39-83` (5 tests,
  `--partial` plus `refute`, against `/lint/run.sh`). The latter's independent
  property is "`/lint/run.sh` actually landed in the consumer image", and its
  header already records that scope.
- `smoke_helper_spec`'s header (`:207-212`) documents the duplication as
  deliberate ("put the real xhost branch inside base's own gate so a deletion or
  inversion goes red here, not only in a consumer's build"), so spellings (1) and
  (2) are a decision. (3) and (4) are not.
- The two weak spellings predate the strong one: `bbc011e0` (2026-06-24) versus
  `819577ed` (2026-08-05, "make the shipped smoke specs able to fail", #884) --
  residue from that sweep, which already handled `display_env.bats`.

**Why it matters.** `run_sh_spec:651` is worse than absent: it occupies the name,
so someone grepping for "the Wayland test" finds it and stops. The three
`template_spec` greps are the classic weaker restatement -- they cannot go red
while the behavioural test is green, but they **can** go red when behaviour is
correct and the source is refactored.

**Note:** there is no fail-open here. `smoke_helper_spec` and the shipped
`display_env.bats` both really execute the branch, so a deletion or inversion goes
red today in base's gate and in every consumer's devel-test stage. This is a
name-squatting duplicate, not a member of the #1032 / #1071 bucket.

**Fix.** Delete `run_sh_spec.bats:651` and `template_spec.bats:3385/:3391/:3397`.
`smoke_helper_spec:216-243` already proves those three things, by execution rather
than grep. Keep the shipped `display_env.bats` and record its reason in its header
the way `smoke_helper_spec` does, so the next audit does not reopen this.

**Care:** removing four `@test`s moves the per-file counts enforced by
`script/test/sync-doc-counts.sh` / `check_test_md_drift.sh`, so TEST.md must be
updated in the same PR or the doc-counts lint goes red.

Do not cost-justify this: the 2077 ms belongs to `smoke_helper_spec:216-243`,
which is being **kept**; the actual saving is sub-second, and per ADR-00000008 a
shard's floor is set by the longest spec **file**, so removing one test from
`run_sh_spec` does not move it. The argument is signal, and the mutations support
it fully.

## How to verify

Each item states its own mutation:

1. Point a locale arm at the other locale's heredoc and require the locale tests
   red. They are green today.
2. No behavioural change -- assert the four mirrored comment sites agree with the
   file-granularity mechanism, and that the baseline count is derived.
3. Remove the install and require the pin roster, the guard and the docs to be
   consistent in the same commit (`test-tools-pins.sh` refuses a declared pin with
   no probe, so a partial removal fails loudly).
4. Invert the xhost branch and require the surviving tests red -- that already
   holds for `smoke_helper_spec`, which is why the other four can go.
