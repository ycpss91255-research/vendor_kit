## 決議（2026-09-17）

`just diff` 改為**三方比對、只顯示、不寫回**。

- 三份：基準（你上次確認過的範本）、新版範本（image 內 `/dist`）、你的檔。
- 基準放 **`.vendor_kit/baseline/<name>/`**（每個工具各一份，以 `<name>` 為目錄；vendor_kit 不綁定任何特定工具），進 git，vendor_kit 擁有、**納入 verify 檢查，人不能手改**。內容 = 渲染後的初始檔副本 + metadata（image、每檔 sha256）。
- `init` 從第一版就寫基準。init 碰到檔案已存在：**明確 warn、絕不覆蓋**（不再只是一行 info），仍存一份當時的範本當基準，之後 `just diff` 才有三方可用。
- 更新基準用獨立指令 **`just accept <name>`**，語意「這版我全看過了」，寫入的是新版範本；`diff` 結尾只印提示不詢問（`docker run --rm` 沒有 TTY，且要保持可管線）。
- 缺基準 → 退回二方並明說「無基準」。
- **結束狀態語意**：0 沒差異／1 工具有改動／2 可能重疊（給 CI 用）。
- 兩個工具 init 到同一個 dest → **報錯**。
- 第一版：每個檔分成五類（沒人改／只有工具改／只有你改／兩邊都改／你已套上相同內容）＋ 印「舊→新（工具改了）」「舊→你的（你改了）」兩份 diff，行級只標「可能重疊」；處理新增／移除的範本檔（取新舊 init.toml 聯集）。第二版：自寫 diff3（difflib 之上約 100–150 行，測試要含：上下文重疊、零長度插入、行號投影）。

## 已排除

- A 維持二方：工具改的和你改的混在一起。
- C 三方自動合併寫回：違反「工具不改使用者檔」；merge3 套件是 GPL；真 diff3 自寫即可，成本與 B 相同。
- 基準放 `.<name>/`：升級整批覆蓋、fresh clone 沒有。
- 基準用舊 image digest 重取：容器內沒有 docker，啟動器要變厚；#14 引入變數後還要存變數；不當自動備援。
- diff 結尾問 y/N：無 TTY。
