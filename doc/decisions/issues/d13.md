## 決議（2026-09-17）

要鎖，用 **flock，鎖的是專案目錄本身**（`open(/repo, O_RDONLY|O_DIRECTORY)` 後 `fcntl.flock`，務必 flock 不是 lockf）。

- 一個專案一把鎖：install 排他、verify 共享；tools.just 等共用產物的寫入也在鎖內。不建鎖檔（放 `.vendor_kit/` 或 `.<name>/` 會被整批替換、inode 換掉鎖就失效；放根目錄要改使用者的 .gitignore）。
- 拿到鎖後**重讀 `.version` 與印記**；已是目標版本就跳過複製、仍跑一次 verify。取鎖前先做 image pull 等不需互斥的事。
- 逾時預設 **60 秒**（`VENDOR_KIT_LOCK_TIMEOUT` 可改；0 = 立即失敗給 CI；-1 = 無限）；1 秒後印「另一個 vendor_kit 程序仍持有鎖，可用 docker ps 查看」，每 5 秒重印；逾時只回非零、不刪鎖、不殺持鎖者、不寫入。
- 鎖不支援（NFS、ENOTSUP 等）→ **直接失敗**並印清楚訊息，`VENDOR_KIT_NO_LOCK=1` 明確接受風險才放行；**絕不自動退回 mkdir 鎖**。
- 暫存目錄 `.<name>.tmp.<urandom 8 hex>`（容器內 pid 恆為 1）；持鎖時順手清殘留；`docker run` 加 `--init` 讓 SIGTERM 能傳給 Python 清理。
- 執行中 `.version` 被改（另一邊 git checkout）：照原本讀到的版本裝完，下次 just 再對齊。
- 發布：第一版維持鎖內 rmtree+rename；「install 期間主機端腳本可能撞到空窗」明寫進限制。要真原子替換時用 Linux `renameat2(RENAME_EXCHANGE)` + 失敗退回，不做 symlink 切換。
- 平台範圍（2026-09-17 定）：Ubuntu/Linux amd64 + arm64（WSL2 視同 Linux；macOS 不在範圍），flock 在此範圍內可靠；NFS 明寫不保證並印警告。不用架構專屬的系統呼叫（RENAME_EXCHANGE 不採）。
- 測試閘門：兩個容器同版本／不同版本／不同工具同時 install、中途 docker kill 再重跑、鎖逾時與不支援時不寫入且使用者檔不變。

## 已排除

- A 不鎖：擋不住 rmtree→rename 空窗，同版本互刪。
- B mkdir 目錄鎖：SIGKILL／OOM／docker stop 逾時必留殘鎖，殘鎖判定（PID 跨 namespace 無意義、mtime 心跳）不可靠。
- symlink 切換：第一次遷移仍要 rmtree、要 GC 舊版、verify 要處理 symlink。

## 對前例資料的更正

Nix 用的是 flock 不是 fcntl；macOS Docker Desktop 上「同一 VM 內容器互鎖仍可」沒依據（實際上容器↔容器也壞）；WSL#3574、Debian#928347、lockfile 預設 10 秒等引用錯題或捏造。

## 連帶

第 5 頁 install 泳道加「取鎖／重讀／跳過／釋放」、verify 加共享鎖；第 1 頁專案檔案存取模組加「鎖」單元。
