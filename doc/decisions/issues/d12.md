## 決議（2026-09-17）

verify 的**基準 = `.version` 鎖定的 image 裡的 `/dist`**，不是本地印記。

- verify 本來就在該工具自己的 image 容器裡跑（`_vk` 用 `.version` 的 image；`Dockerfile.dist` 把 dist COPY 進 `/dist`），所以直接對 `/dist/files` 與掛進來的 `.<name>/` 做「兩棵樹 diff」：**不用多起容器、不碰網路**（實測 200 檔雙邊 hash 42 ms；docker run 本身 250 ms）。
- 比對範圍：檔案集合（**缺檔、多餘檔都失敗**，只豁免 `.stamp`）＋內容 sha256 ＋執行位（只比「該 +x 的有沒有 +x」）＋型別（lstat 不跟隨 symlink；**第一版禁止 symlink**）；不比 mtime、owner、完整 mode。
- 同一個「兩棵樹 diff」函式給 install（決定寫什麼）、verify（報錯清單）、release-test 用。
- 印記 `.stamp` 降級為「裝的是哪版」的快取鍵 + 給人追溯：第一行改用啟動器 `--self` 傳進來的 `.version` 字串（解掉 Dockerfile.dist 把 digest 寫進自身的循環），不簽章，格式不合法視為不可讀 → 走重裝。
- 多餘檔中止的理由是營運（`.<name>/` 是整批替換的目錄，下次升級會無聲刪掉它；警告不可強制），不是安全。前提：工具執行期不往 `.<name>/` 寫 log／快取（base 的 compose.yaml、.env.generated 在專案根，符合）；release-test 加「跑 wrapper → verify 仍過」閘門強制。
- verify 失敗：中止並提示刪掉重裝，**不自動重裝**（會無聲毀掉手改）。
- `.vendor_kit/` 是例外：沒有 /dist，基準 = image 內程式重新產生 vendor.just 再比；baseline/ 納入檢查。
- 時間預算 0.5 秒指**容器內 verify 函式**（固定 200 檔 + 固定總 MB）；含 docker run 的端到端另外量。
- 第一版不做 stat 快取；dist 上百 MB 再把印記升級成 git index 式快取疊上去。
- 平台範圍（2026-09-17 定）：Ubuntu/Linux amd64 + arm64（WSL2 視同 Linux）；執行位仍只做單向比對以保持簡單。多架構 image 的 dist 內容必須與架構無關（否則換平台後 verify 會要求重裝）。

## 已排除

- A 只比印記 hash（現況）：抓不到多餘檔、執行位、symlink；印記與被驗檔同一使用者可寫，只防不小心。
- B 印記 + stat 快取（原草稿傾向）：基準仍可寫；快取只省約 10 ms 卻帶來 mtime 粒度、同長度改寫漏抓、跨平台誤報、兩條驗證路徑。
- 印記簽章：私鑰只能放 image 或使用者機器，等於沒簽。

## 對前例資料的更正

Terraform 其實每次 plan/apply 都對 provider 目錄重算 hash 跟進 git 的鎖檔比（最像我們的前例，agy 寫反）；Go 的 verify 基準也是本地可寫檔；pip 只重寫 RECORD 不驗；pnpm 原始碼註解明講本地完整性驗證「does not make a store writable by untrusted users safe」。

## 連帶

第 5 頁 verify 泳道改「兩棵樹比對」；第 1 頁出貨內容讀取多一條線到 verify、印記模組職責縮小；原型 `cli.verify` 直接用已傳入的 `Dist`。
