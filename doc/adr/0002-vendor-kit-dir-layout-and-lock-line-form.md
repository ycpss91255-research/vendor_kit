# ADR-0002：VK 的狀態全收進 `.vendor_kit/`，版本鎖定行只認一種正規形

> Serves: 機制（服務不變量 2、1、3），不建立不變量——本檔記錄版本鎖定行的檔名與格式正規形、`.vendor_kit/` 的目錄佈局，以及 `.vendor_kit/.gitignore` 涵蓋哪些路徑，是「一份版本鎖定行、進 git」（不變量 2）、「只動有紀錄的檔」（不變量 1）與「自動化只碰不進 git 的東西」（不變量 3）的共同機制。

- **Status:** Accepted

## Context

三條不變量都需要同一件事先被定下來：哪些檔在哪裡、誰擁有它。

不變量 2（[第 2 條](../decisions/review/02_invariants.md#2-一個來源版本鎖定行只有一份進-git)）要求每個安裝目錄對「用哪些工具、哪個版本、哪個引擎」只有一份說法。唯一性的單位是安裝目錄，所以一個 repo 可以有好幾個安裝目錄，各自一份版本鎖定行與各自一份 `.vendor_kit/`，彼此不共享。這種佈局要成立，「VK 的狀態放哪」必須有固定答案，否則同一個 repo 裡兩個安裝目錄的狀態會混在一起。

第二份版本真相的漂移是靜默的。所以除了「只有一份」，還要「只有一種寫法」：同一份內容若有兩種合法寫法，比對與 diff 就不可靠，而人不會發現差異在哪。

讀這個檔的有兩端。引擎在容器內，可以帶完整的 TOML 解析；啟動器在主機上，是 POSIX sh，手上只有 `grep` 與 `sed`（不變量 5 把主機依賴壓到 Docker、Git、just，見[第 5 條](../decisions/review/02_invariants.md#5-主機依賴最小除平台既有的基本工具外只需-dockergitjust)）。啟動器要能靠一行 `grep` 找出引擎版本，而且找錯時要能察覺。

不變量 3（[第 3 條](../decisions/review/02_invariants.md#3-自動化只碰不進-git-的東西)）禁止自動化寫進 git 的檔，但 VK 每次執行都要寫快取、產出與紀錄。這兩件事不衝突的前提是「不進 git 的路徑」是一份寫死的清單，而不是每次執行臨場判斷。清單也得放在 VK 自己的目錄裡：`.git/info/exclude` 不進 git，每個 clone 都要重做；使用者的 `.gitignore` 是使用者的檔，改它會踩到不變量 1（[第 1 條](../decisions/review/02_invariants.md#1-使用者寫的內容歸使用者可以建要改先問永不刪永不覆蓋)）。

## Decision

### 1. 檔名與位置

- 格式用 TOML，檔名定為 `version.toml`，每個安裝目錄一份。
- 它與 `version.local.toml`、`cache/<repo>/`、自有 `.gitignore` 一起收進 `.vendor_kit/`。

### 2. 引擎行的正規形

引擎行不靠行號，契約是「唯一符合 `^vendor_kit[[:space:]]*=` 的正規行」（POSIX BRE，不用 `\s`）：啟動器以 `grep` 取得、命中數必須恰為 1，第一行只是 install 寫出的慣例。

命中數是契約的一部分，不是防禦性檢查：0 或 2 以上都表示這個檔不是 VK 寫出來的形狀，此時往下走會拿到猜的版本。

### 3. 工具行的正規形

工具行的正規形是 `[tools]` 表下每個工具一行；BOM、重複鍵與繞過 `[tools]` 表的寫法都不接受，引擎讀到非正規形以 1 結束、列出差異、不動任何檔。

「列出差異、不動任何檔」是這一條的重點：非正規形不由引擎自動改寫，因為這個檔進 git，改它是使用者的 commit。

### 4. `.vendor_kit/.gitignore` 涵蓋的路徑

- `.vendor_kit/.gitignore` 目前涵蓋 `cache/`、`gen/`、`log/`、`version.local.toml`、`.tmp.*`。
- 執行紀錄（`log/`）與暫存檔也在這一層，所以自動化寫它們不違反性質。

這份清單就是不變量 3 判斷「可以自動寫」的界線：在清單內的自動化自己寫，清單外的一律要使用者明確打的 recipe。

### 5. 外部版本追蹤

Renovate 一條 regex manager 追 docker datasource。

regex manager 認的正是第 1–3 節定的那個形狀，所以正規形一動，這條 regex 跟著動。

- 兩份版本真相的例子是 image tag 加上另一個 lock 檔。digest 才鎖內容；tag 只給人與外部版本追蹤工具看。

- 安裝目錄禁止巢狀：`install` 時上層或下層已有安裝目錄就以 1 拒絕（可觀察的行為見 [04 使用者介面](../decisions/review/04_interface.md#執行位置)）。

## Consequences

- 得到：啟動器不需要 TOML 解析器，一行 `grep` 加一次命中數檢查就夠；非正規形在引擎讀檔的那一刻就擋掉，不會帶著半套版本資訊往下跑。
- 得到：安裝目錄可以巢狀之外任意擺放，因為狀態全在 `.vendor_kit/` 之內，不往上外洩。
- 付出：使用者手改 `version.toml` 要照正規形。重複鍵、把工具寫在 `[tools]` 表外這類 TOML 本身合法的寫法會被拒。
- 付出：正規形是三個地方的共同契約——啟動器的 `grep`、引擎的解析、Renovate 的 regex。改格式要同時改這三處，任一處沒跟上就是版本讀錯。
- 付出：`.vendor_kit/.gitignore` 的涵蓋清單與引擎實際會寫的路徑必須一致。新增一種產出路徑時要同時加進清單，漏了就會有檔跑進使用者的 `git status`。

## Alternatives

- **引擎版本固定放第一行，啟動器用 `head -1`。** 省掉命中數檢查，但任何人在檔頭加一行註解或空行就讀錯版本，而且不會報錯。正規形改成 pattern 加命中數後，第一行只剩慣例的地位。
- **寬鬆解析：接受 BOM、重複鍵、`[tools]` 表外的工具項。** 對手改的人友善，代價是同一份內容有多種合法寫法，「只有一份說法」就退化成「只有一個檔」。重複鍵更糟：後鍵蓋前鍵是 TOML 的規則，但看檔的人讀到的是前面那一行。
- **引擎讀到非正規形時自動改寫成正規形。** 少一次人工修檔，但 `version.toml` 進 git，自動改寫等於自動化寫進 git 的檔，直接違反不變量 3。
- **用 `.git/info/exclude` 或使用者根目錄的 `.gitignore` 排除 VK 的本機狀態。** 兩者都不用在 `.vendor_kit/` 裡多一個檔。前者不進 git，每個 clone 都要重做一次，而漏做的症狀是 `cache/` 被 commit 進去；後者是使用者的檔，寫它要走詢問流程，而且每個安裝目錄都要在同一個檔裡加一段。
- **把 `cache/` 之類的本機狀態放到 repo 外（例如 `~/.cache`）。** 就不必排除任何路徑。但同一台機器上的兩個 clone、或 CI 的每次全新 checkout，狀態的歸屬就不再跟著安裝目錄走，而不變量 2 的唯一性單位是安裝目錄。
- 檔名與格式本身（`version.toml`、TOML）沒有實質替代選項可記：TOML 的選定早於本檔，`version.toml` 已是根 `CONTEXT.md` 的名詞條目，本檔只把它固定成正規形的一部分。
