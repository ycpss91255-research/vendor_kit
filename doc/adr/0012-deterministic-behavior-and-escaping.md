# ADR-0012：引擎容器內的語言與時區寫死，行尾與跳脫逐處指定

> Serves: 機制（服務不變量 11），不建立不變量——本檔記錄引擎容器內固定的 locale 與時區、時間戳格式、行尾正規化規則，以及路徑與自由文字在三處介面上的跳脫方式，是[不變量 11「正確性不綁單一平台」](../decisions/review/02_invariants.md#11-正確性不綁單一平台)裡「同一份輸入在每個支援平台得到相同對外結果」的實現機制。

- **Status:** Accepted

## Context

跨平台不一致不會變成紅燈。行尾比對不等價，結果是冒出假的合併衝突、或漏認自己寫過的行；排序隨主機 locale 改變，結果是兩台機器對同一份輸入給出不同順序的輸出。兩者都照樣回結束碼 0，通常只被當成那台機器的個別狀況。不變量 11 因此把「不得只在一個平台成立」定成性質（見[第 11 條](../decisions/review/02_invariants.md#11-正確性不綁單一平台)），剩下的是機制問題：哪些環境變數要寫死、寫死在哪一側、字元怎麼跳脫。

VK 的執行跨兩側。引擎在容器內，那個環境是 VK 自己造的；啟動器在主機上以 POSIX sh 跑，主機的 shell、locale 與時區不是 VK 的東西。所以「固定環境」只在容器這一側做得到，主機那一側只能靠跳脫，把主機的 shell 當成不可信的轉發層。

字元問題有兩類來源。使用者的路徑可以含空白、`$` 與非 ASCII，這在 Jetson 與 WSL2 上都常見；行尾則是 git 與編輯器在 Windows 端動的手，同一份內容在兩台機器上可能是 CRLF 與 LF 兩種位元組。把它們當例外處理，每個接收端就各自長出一套猜測；VK 的做法是在每個介面上先定好文法。

## Decision

### 1. 引擎容器內的環境寫死

- 引擎容器內固定 `LC_ALL=C.UTF-8` 與 `TZ=UTC`
- 時間戳一律 UTC ISO 8601
- 排序、比對與大小寫轉換不隨主機的 locale 與時區改變

這三條是同一件事的三個面：引擎不讀主機的 locale 與時區，它自己宣告一組。擁有者是引擎 image——環境在 image 裡設好，不由啟動器傳進去、也不由 recipe 臨場設定，否則漏一處不會有人發現。

### 2. 行尾

- 行尾：`dist/` 文字檔一律 LF；append 行比對 CRLF/LF 等價；薄殼 hash 先 CRLF→LF 正規化再算

出貨端只出 LF，導入端不假設拿到的是 LF。這兩句不矛盾：`dist/` 是 VK 控制得到的東西，所以定死；repo 裡的檔是使用者的，經過 git 與編輯器之後行尾可能已經換了，讀它的時候只能先正規化或等價比對。

### 3. 跳脫分三處固定

- 啟動器傳路徑一律加引號（含空白、`$`、非 ASCII）
- 引擎回給啟動器的執行計畫裡自由文字用八進位跳脫
- 執行紀錄的 argv 與路徑逐項 JSON 跳脫

三個接收端的文法不同，所以跳脫方式不同：主機的 POSIX sh、啟動器解析的執行計畫、讀執行紀錄的程式。每一處的跳脫由產生那一側負責，接收端不猜、不補救——啟動器不替引擎的輸出補引號，讀紀錄的那一端不替 VK 修沒跳脫的欄位。

## Consequences

- 得到：locale、時區、行尾、特殊字元這四類差異在每個支援平台上有同一個答案，不必逐個 recipe 重新處理。
- 得到：ADR-0003（行尾等價比對）、ADR-0005（執行紀錄的跳脫）與 ADR-0007（薄殼 hash 的正規化）各自引本檔對應的節，規則只有一份。
- 付出：引擎內不能用主機 locale 的排序與大小寫規則。要按使用者語言排序的輸出，得另外決定怎麼做。
- 付出：CRLF/LF 等價比對與正規化要在每個平台給同一個答案，是跨平台測試要顧的一項。
- 付出：三處跳脫是三套規則，新增一個介面就要指定它的文法。
- 需要同步更新：`doc/decisions/review/02_invariants.md` 第 11 條的「建立或服務它的 ADR」行加上 ADR-0012。
- 驗收：由 ADR-0011（測試與 CI 矩陣）的跨平台矩陣涵蓋。本檔定規則，不定驗法。

## Alternatives

- **不固定容器環境，各處用到時自己指定 locale 與時區。** 不必動 image，代價是擁有者從一個變成 N 個：漏掉的那一處在開發機上照樣通過，只在時區或 locale 不同的機器上給錯答案，而且不報錯（違反 P5）。
- **只認 LF，CRLF 當成不同內容。** 實作最單純，但 Windows 端經 git 取得的檔常是 CRLF，比對會判成「內容變了」，冒出假衝突，正是不變量 11 列出的失效方式。
- **在導入端把使用者檔的行尾一律改寫成 LF。** 比對就不必等價，代價是動使用者沒要求改的檔，踩到不變量 1（[第 1 條](../decisions/review/02_invariants.md#1-使用者寫的內容歸使用者可以建要改先問永不刪永不覆蓋)）的永不覆蓋。
- **三處用同一種跳脫。** 少記兩套規則，但三個接收端的文法本來就不同：POSIX sh 認引號，執行計畫與執行紀錄各有自己的文法，硬套一種只會讓其中兩處要在接收端再解一層。
- **時間戳記主機本地時間加時區偏移。** 資訊不損失，但每個讀紀錄的地方都得先正規化才能排序與比對，那一步遲早會被漏掉；統一 UTC 讓比對是字串比對。
