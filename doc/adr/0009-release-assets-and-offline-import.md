# ADR-0009：Release 資產的形狀與離線導入——旁檔給 digest，已釋出的永不刪

> Serves: 機制（服務不變量 2、10），不建立不變量——本檔記錄 Release 資產的組成（每個支援平台一份 image tar、同名 `.digest` 旁檔、一份 `SHA256SUMS`）、離線導入怎麼從旁檔取得 digest 寫進版本鎖定行，以及已釋出資產永不刪的保存承諾，是[不變量 2「一個來源：版本鎖定行只有一份，進 git」](../decisions/review/02_invariants.md#2-一個來源版本鎖定行只有一份進-git)裡「決定性重建」在提供端的實現機制，同時服務[不變量 10](../decisions/review/02_invariants.md#10-相容性與演進同一個-x-內不破壞x-變動才可能不相容且先公告)的「退得回」。

- **Status:** Accepted

## Context

版本鎖定行的唯一性只管到使用者那一端。使用者手上那一行鎖了 digest，但 digest 指到的東西得由提供端一直留著；一旦被刪，重建就從「照那一行做得出同樣內容」變成「拉不到」，而失效的時間點不在使用者的任何一次改動上。這是不變量 2 已經寫進性質的那一句：決定性重建會在提供的那一端靜默失效。

另一端的壓力是離線。有些機器根本連不到 registry，只有人帶進去的一份 image tar。離線導入若因此少寫 digest、只留 tag，那一行就不鎖內容了——tag 可以被重新指到別的東西。所以離線也必須寫得出 digest，而 digest 不能由導入端自己算：從一份 image tar 算得到的是那一個平台的雜湊，不是版本鎖定行要鎖的多架構 index digest。要讓離線與線上寫出同一行，digest 只能由出貨端另外交出來。

不變量 10 的「退得回」也押在同一件事上。它的可觀察結果是：版本鎖定行還原回舊值之後，舊版內容仍取得回來、仍重建得出來。鎖定行進 git，還原永遠做得到；真正會擋住退版的是舊資產已經不在。

## Decision

### 1. Release 資產的組成

- Release 資產的形狀：
  - 每個支援平台一份 image tar
  - 旁邊一份同名 `.digest` 檔，記那個 image 的正式多架構 index digest
  - 另有一份 `SHA256SUMS` 涵蓋其餘資產

旁檔記的是正式的多架構 index digest，不是那一份 tar 的雜湊。它的用途只有一個：讓離線那條路寫出跟線上一樣的版本鎖定行。`SHA256SUMS` 管的是其餘資產的完整性，不承擔 digest 這件事。

### 2. 離線導入從旁檔取得 digest

- 離線導入（`add --local`）讀旁檔取得 digest 寫進版本鎖定行，所以離線裝到的內容與線上同一份。旁檔缺 → 1

旁檔缺就以 `1` 結束，不退化成只寫 tag。少掉的 digest 不會在當下報錯，只會在幾個月後的某次重建上出現差異。

### 3. 已釋出的永不刪

- 已釋出的 image 與 Release 資產永不刪（第 2 條），舊版才一直取得回來

保存承諾與資產形狀是同一個決定的兩面：形狀決定使用者的鎖定行指到哪些東西，保存決定那些東西還在不在。

## Consequences

離線與線上寫進版本鎖定行的是同一個 digest，所以同一行在兩條路徑上重建出同樣的內容；旁檔缺的情況被 `1` 擋在寫入之前，不會留下一行只有 tag 的鎖定行。退版不需要額外機制，還原鎖定行就夠，因為指到的資產還在。

代價落在出貨端。每次 release 要多交每個平台的 `.digest` 與一份 `SHA256SUMS`；支援平台增加時 tar 與旁檔的數量跟著長。永不刪是永久成本：儲存與已用過的版本號只會累積，發錯的版本也只能另發一版蓋過去，不能撤掉。

`doc/adr/README.md` 的待拍板清單裡有「dist image 單架構 amd64」。那一項若定成單架構，tar 的份數變成一份，旁檔與 `SHA256SUMS` 的形狀不動，本檔不必改。

驗收落在黑箱層：乾淨 fixture 裡拿掉旁檔跑 `add --local`，要得到 `1`，且版本鎖定行不動。

## Alternatives

- **不要旁檔，離線導入自己算 image tar 的 sha256 當 digest。** 資產少一個檔，取件也少一次讀取。不採：算出來的是那一個平台的雜湊，不是多架構 index digest，離線與線上會寫出不同的鎖定行，而兩邊都不會報錯。
- **離線時只寫 tag，不寫 digest。** 離線那條路最短，出貨端什麼都不用多交。不採：tag 不鎖內容，離線裝到的就不保證與線上同一份。
- **digest 也塞進 `SHA256SUMS`，不另設同名旁檔。** 只維護一份清單。不採：那份清單要先解析再挑出對應平台那一行；旁檔同名，`<tar>.digest` 一次讀取就到手，缺哪個平台也直接看得出來。
- **舊資產設保留窗口，過期清掉。** 儲存成本有上限。不採：退得回是不變量 10 同一個 X 內的性質，資產一清，那個承諾在某個時間點之後就作廢，而且沒有訊號。
- **用第三方工具的離線 bundle（imgpkg air-gap bundle）取代自己的 tar 加旁檔。** 格式現成，不必自己定資產形狀。不採理由已記在 [ADR-0001](0001-why-not-existing-tools.md) §2：`vendir sync` 沒有從本機 tar／OCI archive 匯入的介面，走 bundle 就是另一個 binary、另一種格式，與不變量 5 相衝。
