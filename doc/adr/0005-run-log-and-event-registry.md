# 沒有固定格式的輸出不能拿來解析，事件名由註冊表封閉

後續檢查（`sync`、`just vendor_kit test`、下一個可寫 recipe）要看得出上一次執行做到哪裡；要是靠解析給人看的訊息，措辭一改，讀取端就靜默壞掉，這正是[不變量 4](../contract/02_invariants.md#4-永不靜默失敗)要擋的。因此，沒有固定格式的輸出不能拿來解析；這條通則已升格為[不變量 10](../contract/02_invariants.md#10-相容性與演進同一個-x-內不破壞x-變動才可能不相容且先公告)，本 ADR 記錄機制與理由。對外只有契約明定為固定格式的輸出可以解析，包括 [03 輸出](../contract/03_output.md)的結束碼與診斷第一行，以及 [04 使用者介面](../contract/04_interface.md#update)明定的 `update` 查詢結果（每個查詢的工具與引擎各一行）；VK 內部讀取端也只依明定的格式，包括本 ADR 定的執行紀錄 JSONL、事件註冊表與啟動器、引擎之間的 `vk-resolve/<P>` 文法。給人看的措辭與版面一律不承諾可解析。紀錄由啟動器與引擎兩個實作各寫一段，事件名因此由一份註冊表封閉，真本只有一份，放在引擎 image，避免同一件事在兩邊長出兩個名字。建出執行紀錄後，每印一條帶原因代碼的 stderr 診斷，就寫恰好一筆 `diagnostic_emitted` 紀錄，並在 `attributes."vendor_kit.reason_code"` 寫入同一個原因代碼；契約明定在建立執行紀錄前拒絕的情況，以及建不出執行紀錄的診斷，是例外。

## Considered Options

- **開 `--porcelain`**：一次呼叫就在 stdout 拿到結構化輸出，但它是人讀訊息的平行版本，同一件事要改兩處，遲早不同步；對外要解析的需求，由契約明定的固定格式承擔（結束碼、診斷第一行、`update` 每行）。`update` 的固定格式不是平行版本，人看與腳本讀的是同一行。
- **維持只走執行紀錄、不承諾任何 stdout 可解析**：維護者要讓腳本不加選項就能判斷 `update` 有沒有新版；apt、pip 等前例多半在查詢成功時預設回 `0`，是否有新版只能解析輸出。只提供執行紀錄無法滿足這個需求，因此讓 `update` 的查詢結果採契約明定的固定格式。
- **事件名開放，各實作要寫什麼就寫什麼**：讀紀錄的一端永遠不知道會遇到什麼名字，打錯字的事件名不會有人發現。
- **未註冊的事件名只警告、照樣寫進紀錄**：未註冊只可能是實作錯誤，使用者沒有下一步可做；依[不變量 4](../contract/02_invariants.md#4-永不靜默失敗)，警告一樣要指名對象，有辦法處置就列出下一步。照樣寫進紀錄會讓讀取端遇到不認得的名字。
- **註冊表真本放薄殼、隨 repo 進 git**：真本散成每個 repo 一份，引擎升版要改每個 repo 的檔，違反[設計原則 P5](../decisions/design_principles.md#p5-一條規則一個擁有者)。
- **只靠 CI 靜態檢查，執行期不對表**：靜態檢查看不到執行期組出來的事件名。

## Consequences

- 契約明定為固定格式的輸出，改動受[不變量 10](../contract/02_invariants.md#10-相容性與演進同一個-x-內不破壞x-變動才可能不相容且先公告)約束：同一個 X 內只能增加、不改既有的意思，不相容的改動只能隨 X 變動並先公告；其他輸出的措辭與版面不承諾可解析。腳本可以直接解析 `update` 的固定格式 stdout；執行紀錄仍是 VK 內部讀取端判斷執行進展的依據。
- stderr 診斷與 `diagnostic_emitted` 紀錄由同一份診斷資料產生；原因代碼在兩種輸出中必須相同，但多數進度或狀態事件不會印到 stderr，所以反向不成立。
- 事件名是 VK 內部讀取端之間的封閉協定，不是對外契約；VK 不承諾第三方直接解析執行紀錄。新增啟動器事件要一起改 `log.sh` 的內嵌清單，而 `log.sh` 是薄殼檔，改了它，既有 repo 就得先 `upgrade --engine`，所以啟動器事件不能隨手加。
- 別的 ADR 要精確引用事件名或紀錄欄位時，引本檔與真本，不各自複述清單。
- 驗收：release CI 的「內嵌清單 ⊆ 真本」檢查與原始碼的靜態檢查；執行期對表由引擎與啟動器各自的測試涵蓋。
- 內部機制（之後搬到實作 issue）：
  - 事件註冊表 `log-events.txt` 是事件名的有限集合，真本在引擎 image。引擎寫紀錄前對真本查表，啟動器寫紀錄前對 `log.sh` 內嵌的子集查表，未註冊的事件名都當實作錯誤，立即停下、以失敗結束（error，[結束碼](../contract/03_output.md#結束碼) `2`）；未登錄事件名等 VK 自身錯誤，以「VK 內部錯誤」原因代碼（[訊息表](../contract/reason_codes.csv) `VK0056`）報出；CI 另以靜態檢查擋原始碼裡未註冊的事件名。執行期對表擋動態組出的名字，靜態檢查擋寫死的，兩層都要。
  - 啟動器的 `log.sh` 內嵌一份啟動器事件的子集，因為它在容器起來之前就開始寫紀錄、讀不到真本；子集只准少不准多，由 release CI 驗。
  - 執行紀錄不提供關掉的選項；建不出執行紀錄的那次執行以[結束碼](../contract/03_output.md#結束碼) `2` 結束、不動任何檔。
  - 執行紀錄早於任何寫入、拉 image、起引擎；在建執行紀錄之前判定的情況見 [03 輸出](../contract/03_output.md#輸出)的主機前置檢查與 [04 使用者介面的判定順序](../contract/04_interface.md#判定順序)，拒絕時不建紀錄、不寫檔。完整時序見 [ADR-0004](0004-vk-recipe-interface-and-write-boundary.md)。
